# OUO 操作映射

本文件是布局规划到现有原生工具的映射。连接、权限和完整恢复流程参见 [画布读写](../../ouo-business-generation/references/canvas.md)。以当前对话实际提供的工具与 schema 为准；没有的能力说明缺口，不通过其他客户端或自行构造 API 代替。

## 读取最小必要信息

1. 使用 `target_project` 定位准确画布，复用其总览、`revision` 与 `followupRead`。已有准确目标和新鲜总览就直接继续，不重复取概览。
2. 按当前 schema 使用 `read_project` 获取目标节点、相关分组、连接及邻近障碍物。同版分页原样沿用 `nextRead`；版本变化后重新读取，不能拼成混版快照。目标选区外的对象只用于判断边界与连接，不因此获得修改授权。
3. 编辑已有节点时批读精确 `node_ids` 与必要字段，并在支持时使用 `include_revisions=true`；从 `nodeRevisions[id].editRevision` 填写 `expected_nodes`。`nodeRevision` 用于结果交接，不能混用。旧服务只支持单节点读取时按其真实 schema 处理。
4. 首次需要编辑时读取 `get_canvas_editing_contract`，同一有效契约直接复用。只整理现有位置不需要模型推荐或费用准备；新建媒体节点的参数确实需要选择时才读取相应实时契约。

读取几何时保留 `id / type / x / y / width / height` 以及所需显示比例和组边界。字段不存在就按未知处理，不编造节点测量工具。媒体像素宽高、模型比例、快照节点矩形、浏览器实际显示矩形与缩放后的屏幕坐标是不同数据，不能混用。

## 方案如何变成动作

| 规划意图 | 现有动作与边界 |
| --- | --- |
| 新节点放入指定区域 | `create.node.position = {x, y}`；由真实执行器分配身份 |
| 精确移动已有节点 | `update` 只传 `node_id` 和 `position`，附准确 `expected_nodes` |
| 同类局部节点排列 | `layout` 的 `mode` 为 `grid / horizontal / vertical / workflow`，显式选择 `node_ids / origin / gap`，网格按需要设 `columns` |
| 分支工作流局部初排 | `workflow` 依据选中节点之间的真实连接运行原生 Dagre；不会理解全部制作语义，也不会自动规划分组 |
| 组合模式或自由布局 | 计算各节点位置，用 `update.position` 实现；不发送 `timeline / radial / swimlane` 等未声明的 `mode` |
| 建立有意义的分区 | `group` 至少两个真实节点；颜色来自 `groupColors`；已存在的单成员结构按实际读取保留 |
| 调整既有组 | `update_group` 支持名称、颜色和完整成员清单；省略成员表示保留，不能把待追加成员当作完整清单 |
| 移动整组 | 当前没有通用 `move_group`；读取并覆盖获准组的实际成员，逐节点移动，核对原生刷新后的组边界 |
| 关系表达 | 原生 `connect / disconnect` 会影响输入、引用或依赖，仅在请求和业务关系确实要求时修改 |

`origin` 和 `position` 使用画布坐标，不是截图像素。`layout.node_ids` 的输入次序可用于普通排列，但合成顺序必须单独核实已保存的分镜与时间线。嵌套组的实际成员、父组及组边界应一并考虑；不能假设同一节点可任意属于多个组。

当前 `create / update` 不开放任意 `width / height / fontSize / edgeStyle / waypoints / bounds`，不能借 `data`、`content` 或额外参数注入。不能修改比例、时长、模型或正文来改变节点占地；仅排版请求下保留这些设置。没有装饰文本或任意形状能力时，使用现有节点、组名和位置表达层次，不创建无用途生成节点。

`workflow` 只将当前选中集合内部的连接交给原生布局。整理局部时还要检查跨区引用；整图直接 Dagre 不等于按任务完成设计。先连真实关系再局部排版是新建工作流的一种可用顺序，已有画布纯移动则不重建连接。

## 保留制作绑定

剧本默认结构按 [剧本工作流框架](../../ouo-script-to-film/references/canvas-workflow.md) 组织。`sync_production_canvas` 的内置整图投影有自身固定坐标和绑定逻辑，不能把它当作本 Skill 的自适应排版入口。

已有制作先读取并复用真实节点绑定，按其 ID 局部移动，保留来源、任务、参数和成员。后续整图同步可能重新调整绑定节点的位置；再次同步前按实际契约核对冲突和影响，不能承诺手工布局永久不变，也不能自动重复投影修复排版。新建时沿用制作 Skill 的现有保存及绑定流程，不发明新的绑定字段；当前工具无法同时完成所需布局与制作绑定时说明具体缺口。

跨镜头和跨集共享素材保留原来源；空间分区不改变任务依赖。画布连线已存在也不证明已将真实媒体按当前模型契约传入生成参考。整理不会自动补素材、生成首帧、重做结果或开始合成。

## 提交和恢复

- 使用 `edit_canvas` 的有序批次及稳定 `request_id`。默认省略 `connection_id`，无需打开网页确认；使用当前有效的已绑定 Agent 会话时原样保留其授权上下文，不自行构造会话身份。
- 新节点或组通过 `$key` 引用同批更早的创建动作；只使用返回的真实身份继续后批。已有节点一律使用本轮读取的准确修订。
- 当前常规上限为每批 100 动作、200 个明确已有节点、256 KiB 载荷，`layout` 和建组各最多 100 个节点；数值随实时 schema 与契约核对。分批不会扩大权限、绕过锁或规避单个不可分割操作的范围限制。
- 分批前记录区域、已核实对象映射与剩余步骤；每批单独保存、回读并推进。执行或保存不确定时保留原参数与操作身份，使用 `get_canvas_operation` 查询；需要恢复时遵循原操作的 `canResume` 和真实恢复入口，不新建替代操作。
- 权限拒绝、占用、版本冲突或用户接管时停止相关写入。重新读取能解决的冲突在原授权内重新规划；不能覆盖新的人工改动或通过换目标继续。
- 已明确核实保存、随后发现几何问题时，使用最新修订和新请求提交准确修正；这与重试受理未知的原请求不同。

编辑返回 `persisted=true`、`presentOnCanvas=true`、非空 `verifiedRevision`，且项目与真实对象映射匹配本次意图时，可以报告保存，不无条件追加查询。缺少这些证明、结果不匹配或状态未知时继续查原操作；分批只报告已核实的范围。

## 保存、几何和视觉证据

保存回执证明持久化，节点几何回读证明当前结构，真实界面截图才能支持视觉结论。需要补充几何信息时按需回读相关字段，不为验图重复保存。

当前编辑契约不提供通用截图或任意脚本预览接口。宿主具备浏览器或图像能力并且当前请求允许访问该准确画布时，查看真实页面；不要新建临时 MCP 客户端、猜测导出地址或为截图打开第二次登录。页面未打开不妨碍原生编辑。缺少视觉能力时说明实际完成的结构与几何检查，保留视觉待核验项。

当前工具目录存在 `present_canvas` 且活动能力有效时，可以按用户查看意图呈现已保存的准确对象；临时框选不产生保存证明。`move_viewport=true` 只用于明确的聚焦意图，用户控制是否跟随；创建、连线、分组和排版已有编辑活动呈现时，无需逐动作额外调用它。
