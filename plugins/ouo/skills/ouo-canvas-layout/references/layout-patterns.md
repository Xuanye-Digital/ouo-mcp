# 布局模式与视觉组织

用于结构选择、混合布局和生成后的视觉审阅。先识别关系，再选择版式；同一种关系也可以因节点规模、尺寸、阅读任务和原有结构采用不同空间安排。

## 结构与风格分开决定

结构回答“先看哪里、什么属于一起、如何继续”；视觉处理回答“怎样区分主次、控制密度”。创作型画布以内容关系形成整体构图，再处理局部对齐、留白、分组和有限组色。换颜色、手绘描边或给规则网格增加轻微偏移，不能替代构图。

| 关系与目的 | 布局候选 | 判断依据和容易误用的情况 |
| --- | --- | --- |
| 有明确输入、处理与输出 | 左右或上下的分层主线 | 按真实依赖排序；不要用节点创建时间代替执行关系 |
| 一个来源供多个任务使用 | 共享锚点、扇出、主干加分支 | 结合全部引用与实际端口方向选位置；共享素材不因引用次数多而复制多份 |
| 多项输入组成一个成果 | 汇聚、并行输入分道 | 汇合节点突出且能追踪来源；不要把仅供比较的结果接成合成输入 |
| 按时间或剪辑顺序审阅 | 时间带、分段序列 | 长序列按已有章节或场次断开；空间折行不改变实际顺序和引用 |
| 比较多个方案 | 并列栏或对照矩阵 | 对应维度保持一致的阅读方向与对齐；独立方案不互接上游 |
| 浏览同类素材 | 分类分区加局部网格 | 网格利于扫描同类项；不同职责不能全压进等权网格 |
| 实体、类别及层级 | 树形、分区目录 | 层级来自内容归属，不凭标题推断业务依赖 |
| 一个主题向外探索 | 中心分支、自由分区 | 适合主题关系；不为了画成放射状给无关生成节点添加引用 |
| 迭代版本或反馈 | 版本序列、迭代分区 | 原生生成依赖不等于概念反馈；不构造工具不允许的循环 |
| 混合生产任务 | 内容簇、共享锚点与有向接续 | 各簇按自己的内容展开，避免所有阶段各占一个等大的矩形 |

比较方案时先排除硬问题：超出授权范围、破坏业务关系、丢失内容、覆盖原作或明显重叠。其余按当前用户任务权衡主路径是否清楚、必要连接是否易追踪、区域是否紧凑、能否继续增补。没有通用的固定权重，也不以完全无交叉为代价牺牲真实引用。

## 关系簇构图

适用于用户希望画布像逐步搭建的创作工作台，或已指出全图方正、等距、机械的情况。目标是让关系决定邻近与展开方式；比较矩阵、资料目录和用户指定的整齐结构仍按其用途处理。

**按共同工作成簇。** 从真实场次、情节段落、共同输入、强关联引用或需要一起审阅的任务识别小集合。节点类型只是一个线索；不将所有图片固定放左侧、所有视频固定放右侧。空间簇可以跨原生组表达邻近，不能擅自改组成员或复制节点来制造归属。

**先放锚点，再形成邻域。** 保留用户已有锚点，安排入口、关键共享节点与成果。共同引用多的节点可位于使用者之间或某簇边缘；结合原生输入输出方向、标题和组边界比较位置，避免为了居中而让连线反复折返。独立簇的位置由相互关系决定，不要求顶边、底边或中心线全部对齐。

**局部有序，整体有变化。** 簇内需要比较或顺序扫描的节点可以对齐；围绕共同输入展开的节点可以形成短分支、错层或局部扇出。不同簇的占地和密度随成员及真实尺寸变化，允许主线在明确接续处转向。不要将“自然”固定成三角形、阶梯或每行少一个节点，也不要用随机偏移、旋转或同一错位步长装饰网格。

**让留白承担关系。** 经常一起操作的节点距离较近，独立段落之间留出转换空间，共享节点周围保留引用通道。留白不必四边等宽；它可以形成簇间入口、主线转折和后续增补空间。不是为获得不规则轮廓而把相连内容推远，也不把所有空处补满。

**用算法起稿，再看构图。** 对连接密集的小集合，可以借鉴“相连节点靠近、互不关联节点适当分开”的关系吸引方法；有序分支可先局部运行原生 `workflow`。随后检查长标题、实际矩形、已有组、镜头顺序和全图疏密。力导向并不理解剪辑与制作职责，不将整集交给它后直接作为完成稿。OUO 没有相应 `layout.mode` 时，以已有 `update.position` 实现规划位置，不添加运行依赖或猜测工具模式。

**用相同内容判断变化。** 需要对比构图时，保持节点集合、显示尺寸、内容、成员和必要引用一致，检查实际改变是否来自位置与邻域。总览应看到大小不同的内容聚合与清楚的接续；正常操作尺度应能读标题、辨认顺序和追踪引用。不能通过删边、合并业务节点、改画幅或隐藏难看的区域来通过视觉检查。

## 剧本到成片

沿用剧本 Skill 的节点职责和制作规格；以下只决定位置。逻辑上“剧本、脚本、共享素材、镜头、合成”的关系，不要求五列等宽或全图同一排列。

- 入口区：原稿与主脚本邻近，读者能找到本集起点；原稿全文仍保存在真实文本节点中。
- 素材：母图与必要变体邻近；仅供某一场次的素材靠近该场次，跨场次素材放在实际引用密集处或簇间接合处，跨集素材保留公共位置。不为归档方便将全部素材强制收进一条长列；已有明确类别组时保留其成员和语义。
- 镜头：遵循已保存的集内剪辑顺序。按真实场次、连续段落与共同使用素材形成内容簇；各簇可有自己的展开方式，镜号与组名帮助识别接续。长序列的折行由内容接点决定，不按固定列数填满巨大矩形。
- 成果区：本集合成靠近镜头序列出口，准确片段顺序来自已保存剪辑计划；不依靠坐标顺序决定合成顺序。

仅供比较的结构示意：

```text
方案一：以执行关系为主
原稿 / 脚本 -> 共享素材区 -> 按场次分带的镜头 -> 本集合成

方案二：以创作工作台为主
原稿 / 脚本         场次甲的镜头簇
         跨场次共享素材
                   场次乙的镜头簇 -> 本集合成
```

箭头只表达示意中的逻辑方向，不能照抄为额外业务连接。选择取决于实际引用、节点数量、现有布局和用户工作方式，不以示例名称或数量触发固定模板。

跨集共享区不强塞进某一集制作组。多集画布保持各集入口和出口可辨认，新增一集不移动无关旧集。用户指定竖向主线时保持该方向；9:16 视频仍可以横向编排，16:9 视频也可以纵向编排。

## 几何与留白

以真实节点矩形及可见标题区域计算占地。新增对象缺少真实尺寸时使用有依据的保守估算，并在保存回读或实际界面可见后核对；未知尺寸不能被当成“无重叠”的证据。

- 使用区内间距、分区间距和主通道留白等少量角色。区间留白通常大于区内，但数值由实际节点尺寸与连接密度决定，不固定为某一像素值。
- 采用局部行列时，下一节点从前一节点的真实边界加所需间距开始；下一行越过本行最高节点及标题区。自由簇逐项检查相邻矩形，不强制折回统一行列。不要用固定坐标步长容纳不同高度的横竖屏节点。
- 将外置节点标题、分组标题、组边框和展开面板纳入检查。以当前实现为准，组边界至少可能在成员左、右、下各外扩 32 个画布单位，上侧外扩 64 个单位；这是实现边界参考，不是通用审美间距。
- 预留分支通道和成果周边空间，避免主干穿过密集素材区。实际连线轨迹由原生画布决定，只能根据真实截图确认是否穿过节点。
- 处理同级分区之间的碰撞；父组包围成员是有意包含，不能误判为应拆散的重叠。扩展局部时也检查邻近未编辑区域的完整边界。
- 超长组名和节点标题需要真实界面检查。允许改名时保留其内容身份；不能为缩短标题删除区分版本或镜头所必需的信息。

几何初检可使用外扩后的矩形。两个矩形只有在横轴和纵轴都相交时才重叠：`A.left < B.right && B.left < A.right && A.top < B.bottom && B.top < A.bottom`。纯连线路径、文本实际换行和界面展开状态仍需视觉证据。

## 消除机械感的具体判断

| 观察到的问题 | 优先修正 |
| --- | --- |
| 所有东西平铺成等权矩阵 | 识别真正需要一起工作的内容簇，重新安排锚点、邻域和簇间接续 |
| 分过组仍像几个并排的大柜子 | 根据成员与引用改变各簇起点、展开方向和占地，规划时省去无职责的外层框；已有原生组仅在授权范围内调整 |
| 每个簇都被整理成同样大小的矩形 | 先容纳真实成员，再检查边界；不补空节点，不要求独立簇外轮廓对齐 |
| 素材全在左边，长线跨过整片镜头 | 将获准移动的共享节点或原生组靠近真实使用区域，结合全部引用与端口重新定位 |
| 全图一条长链，来回滚动才能理解 | 按真实阶段或场次分段，保持接续清楚 |
| 区区套组、每个单节点都有框 | 保留有职责或操作意义的组，避免装饰分组 |
| 共享资源到处复制 | 保留准确来源，将共享区放近使用者 |
| 连线拥挤 | 调整分支顺序、素材位置和区间通道，保留全部必要连接 |
| 竖屏节点压住下一行 | 按实际显示高度及标题区重新计算行高 |
| 网格只做小幅随机错位 | 重做簇间构图；簇内保留需要的对齐，把变化用于表达内容关系 |
| 每个组各用一种颜色 | 按少量语义统一组色，同时保留文字与位置线索 |

正常操作尺度下先看入口、主线和成果是否可辨，再看局部标题与连接。小比例总览只用于判断分区与整体平衡，不能要求所有节点正文同时可读。素材尚未生成时评估其结构和实际占地，不将占位状态当成审美失败，也不为填满画布启动生成。

## 方法来源

以下公开 Skill 仅作为方法参考，执行本 Skill 无需安装它们；采用经过 OUO 契约约束的独立写法：

- [Excalidraw Diagram](https://github.com/coleam00/excalidraw-diagram-skill/blob/main/SKILL.md)：避免等权方框、统一容器和全图卡片网格，让空间结构表达关系，并在渲染后修正。OUO 使用原生节点，不套用其形状、字体或尺寸要求。
- [Claude Canvas](https://github.com/AgriciDaniel/claude-canvas/blob/main/skills/canvas-layout/SKILL.md) 及其布局参考：借鉴关系吸引、分区采用不同方法和算法后再调整位置。未照搬自动阈值、网格吸附、节点数限额或脚本依赖。
- [Canvas Design](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md) 的 `Organic Systems`：借鉴自然聚合、模块生长与空间节奏。OUO 保留完整业务内容和原生外观，不采用艺术海报的稀疏文本、任意尺寸或静态图片交付方式。
- [Obsidian Canvas Creator](https://github.com/axtonliu/axton-obsidian-visual-skills/blob/main/obsidian-canvas-creator/SKILL.md)：先分析层级与分区、按内容选择布局、检查节点占地。未照搬其固定间距与算法示例。
- [baoyu-infographic](https://github.com/jimliu/baoyu-skills/blob/main/skills/baoyu-infographic/SKILL.md)：将信息结构与视觉风格分开，并按任务选择结构。OUO 布局使用原生节点，不沿用其默认图片生成流程或关键词固定版式。
