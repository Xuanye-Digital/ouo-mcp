# 模型选择、生成与原生预览

## 默认交互与调用通道

默认在当前聊天展示确认卡、进度卡和结果预览。用户只需提出创作需求并确认付费生成，不需要指定工具名或另行要求展示卡片。

普通创作流程通过当前对话的原生 OUO 工具执行，实际工具名可能带宿主的命名空间前缀。工具尚未加载时先使用宿主的工具发现、刷新或插件连接机制恢复；仍不可用时停止提交，按用户目标简明说明当前操作暂时无法完成及可行下一步，不要求用户自行检查连接或排查配置，不自动编写临时 MCP 客户端、运行脚本或通过命令行 HTTP 请求替代插件。独立客户端返回 JSON 无法把交互组件关联到当前聊天。

原生 `submit_generation` 已提供一张自动更新的进度与结果卡。提交后保留原 `taskCode`，由这张卡查询同一任务并在结果就绪后展示图片或视频，不再追加进度或结果展示调用。后台状态查询及回执恢复使用 `get_generation_task`，只返回数据，不打开第二张卡。只有用户要求重新查看，或已确认原卡未显示、丢失时，才用 `get_generation_result` 或兼容入口 `show_generation_result` 打开已有任务的卡片；不重新生成、不重复扣费。连接旧服务时遵循实际工具契约，不假定旧版任务查询已经去除卡片。

普通问答与画布选择按返回的交互方式继续，包括 `clientContext.proactiveTextFallback=true` 时当轮展示真实文字选项。宿主明确声明不支持 MCP Apps 时，按对应流程提供文字费用确认或下载链接。工具未加载、协议报错或诊断脚本未显示图片，均不足以判断宿主的卡片能力。用户明确要求开发诊断时可执行相应调试。

### 表单展示后立即等待

下一步依赖用户的选项、项目、素材、方案或费用确认时，先合并本次缺少的必要问题并调用对应交互工具。原生表单返回 `selected` 或 `answered` 时按实际用户输入继续。仍待回复时，按返回的交互方式展示内容并结束回合。等待期间不继续工具、命令、轮询或追加另一张卡。收到实际回复后，沿用原表单、草稿或制作的身份及准确版本。

只有用户实际提交的回复才能用于继续；上下文更新、送达回执或等待状态不代表用户已回答。送达未知时先核实，保留同一回复，不重复发送。仅展示进度且原授权允许继续时不必等待。

## 授权状态

使用当前连接执行请求；账户或其他业务只读调用成功时不重复登录，不索要 Token。仅明确的认证失败触发恢复，例如 `MCP authentication required`、`AUTHORIZATION_REQUIRED`、401 的 `AUTHORIZATION_REJECTED`、`invalid_grant`、`refresh token does not exist` 或明确授权过期。403 权限拒绝不等于登录过期；工具未加载、网络错误及 HTTP 503 也不是重新登录的依据。服务暂不可用时按 `Retry-After` 有限重试只读请求，持续失败则说明当前操作受阻，不承诺自动恢复。

确认授权失效后，下一次 OUO 指令先调用一次原生 `get_account`，让当前宿主处理认证挑战；正常操作无需额外查询账户。首次失败就在当次实际发起或加入一次宿主登录，不能只发提醒。认证挑战或恢复提示本身不证明授权页已打开，也不证明已有登录正在进行。输出遵循 [用户可见输出](../SKILL.md#用户可见输出)。

### 授权页面只打开系统浏览器

1. 优先使用当前宿主的登录动作，由宿主打开系统浏览器；确认已有未完成登录时等待原回调，不启动第二条流程。只有宿主确认后才说授权页已打开。
2. 授权已启动后不再打开返回链接，不用内置浏览器、浏览器自动化、额外标签页、脚本或另一条命令补开。打印授权 URL、暂时没有输出或工具尚未刷新，都不是打开失败的证据。
3. 等待原流程成功、明确失败或用户取消。失败或取消后当前回合不循环重试；用户后续发出新 OUO 指令或明确要求重试时，重新核实并允许至多一次恢复。无法启动时只给已核实的登录入口与具体动作，不伪造按钮或要求用户排查配置。
4. 成功回调后自动用原生 `get_account` 核实原账户与空间，再读取原操作；不要求用户重述需求或回复“已登录”。不读取浏览器页面、Cookie 或凭据判断结果。恢复成功后，旧错误及工具尚未刷新不能再次触发登录；按需使用宿主的发现或刷新入口。

没有重连工具且没有进行中的登录时，才考虑宿主支持的 CLI。先从当前连接信息取得真实服务名，用 `codex mcp get <原服务名> --json` 核对服务身份、地址和 OAuth 资源，并取得共享当前宿主配置及凭据存储的证据；仅名称或 URL 相同不足以采用 CLI。核实后只运行一次 `codex mcp login <原服务名>`，保留原环境，不添加连接、不传 `-c`、不切换 `CODEX_HOME` 或凭据存储、不用脚本代替登录。之后仍须由当前对话的原生账户调用验证。不能退出账号、删连接、清令牌、重装或另建配置；无可核实能力时仅给已确认的宿主管理入口，不让用户执行命令或转发日志。

用户在卡片中实际点击重新登录时，按上述流程发起或加入宿主登录；点击本身不代表登录完成或费用确认。保留原需求、任务、确认记录和操作身份；恢复后先读取原状态。原受理未知、已取消或已停止的写入不自动继续；只读请求可直接恢复。继续创作前重新核验模型、参数和报价，取得匹配的费用确认或核实仍有效的原授权，不切换生成器、不重复提交。

### 授权成功后仍无法访问

宿主确认原连接的 OAuth 回调成功，只能证明登录完成；当前聊天的原生 `get_account` 成功后，才能报告访问恢复。如果回调成功后仍提示需要认证或工具不可用，保留“登录已完成、当前聊天访问待核实”的状态，后续“再来”“继续”也沿用该状态。此情形先使用宿主已支持的同一连接重载或工具发现动作，再只读核验一次；不能仅凭相同的认证提示或用户重试就重新授权。只有宿主已重载原连接，并明确拒绝当前保存的授权，才按新的认证失败处理。原生读取成功后结束待核实状态，以后明确发生的授权过期仍按新的认证失败处理。

没有可调用的连接重载动作时，说明“授权已完成，但当前对话仍未恢复。请重启 Codex，再回到这条聊天重试。”其他宿主使用其实际应用名。不虚构刷新按钮，不把再次登录作为默认下一步，也不承诺重启一定恢复。未取得证据时不能断言凭据存储不一致、旧连接缓存或服务端故障。不要求用户提供令牌、日志或配置；原任务与保存状态继续按真实回执处理。

## 只读模型查询

当用户询问“有哪些模型”“可用模型”“支持哪些图片或视频模型”或类似问题时，直接调用 `list_models`，分别查询 `image` 和 `video`，优先用 `detail=selection`。要求完整清单时按 `nextOffset` 继续读取，不能将筛选后的 `total` 当作全账户的 `availableTotal`。只读查询不调用报价、提交、取消或任何生成工具。

回复只展示当前空间实际返回的 `displayName`、`modelName` 和类型；如果没有展示名就展示 `modelName`。不要把内部工具名、模型 fallback、配置文件、Token、空间 ID 或再次调用指令展示给用户。模型查询失败时，说明授权或服务错误，并给出用户能执行的下一步。

卡片的完整回复通过 MCP Apps 模型上下文传递，聊天消息只保留用户可读内容。读取实际随消息到达的结构化回复并保留原始绑定字段，不要把协议 JSON 或内部 ID 复述给用户。只有上下文而没有实际用户消息不能视为确认；缺失结构化回复时，不从自然语言臆造草稿版本、方案 ID 或回复 ID，应重新展示当前卡片。

## 按任务选择模型

模型描述供当前 Agent 决策使用。用户没有指定模型时，先从其实际创作目标选择当前账户可用的候选，再将选择用于创作方案；不要先要求用户阅读模型介绍或测评页面。

1. 调用 `list_models`，创作选型使用 `detail=selection`、`for_generation=true`，根据明确需求传图片 `task_type` 和目录声明的 `required_capabilities`。只有确实已收到可用于当前任务的参考图时才传 `has_reference_image=true`。逐模型的 `description` 是面向 Agent 的适用任务与短板；需要细分时查 `guidance.taskFit`、`taskMatch`、`taskConditions`。需要业务原文、完整测评方法或榜单时再用 `detail=full`，其中 `businessDescription` 保留上游规格。
2. 把目标细分到实际操作：从零人物写真、已有角色换装换景、写实风景、奇幻场景、商品材质特写、含字海报、信息图、叙事插画或局部修改。不能把“带参考图保持身份”当作“从零人物最好”，也不能把电影室内样张当作自然风景优势。
3. 根据 `taskFit` 选择：先考虑符合当前输入条件的 `recommended`，其次 `candidate`。`conditional` 需要先满足注明的版本或参考图条件；未研究的任务不编造专长。用户明确指定可用模型时尊重该选择，只有参数或能力不符时说明问题。
4. 读取所选模型的 `get_model_parameters`，根据用户要求构造参数后，在同一工具传入 `model_param` 进行只读预检；空对象用于发现缺少的必填参数。用户明确设置优先，其次是有当前任务依据的选择；其他可省略控件不必逐项追问，不自行选择最高分辨率、最长时长或更多产物。当前服务返回 `defaults.values` 时，它只包含局部校验过的顶层 Schema 默认值，不含条件模式默认值，也未应用到请求；忽略 `ignoredFields`，不能把 `requestExample` 当默认。采用任何提示值后仍须按完整 Schema 和 `rules` 重新预检，模型或模式改变后重读。旧服务以实际 Schema 的 `default` 为据，缺失时不猜。
5. `validation.status=needs_input` 时按 `missingFields`、`findings` 和当前创作目标补参；只有仍缺少影响结果或费用的选择时才询问用户。`invalid` 时修正报告的问题；`review_required` 时继续检查 `rules`、素材用途和可用性。工具不自动填入默认值、不改写提示词，也没有访问素材或核验归属。Schema 通过不等于可以提交；真实报价与明确确认仍然必需。
6. 已有草稿时可调用 `recommend_models` 并传准确的 `task_type`；没有草稿时直接依据模型查询结果选择，不为推荐而新建草稿。选择模型不等于同意付费生成。

对用户通常只说选择的模型及一句与当前任务相关的理由。仅在用户要求对比、询问依据或影响选择的条件尚未满足时展开说明；不要默认输出研究报告、完整来源列表或让用户承担内部选型过程。

`query` 只按模型标识或显示名筛选。筛选无结果时根据当前目录调整条件或说明暂无合适入口，不回退到记忆中的默认模型。`required_capabilities` 必须取目录已声明的精确值；声音开关、尺寸、比例和时长要通过所选模型的参数契约核验，不凭空增加 `audio` 等能力标识。视频暂不使用图片的 `task_type`。用户已指定可用模型时读取并预检该模型，不用通用推荐覆盖其选择。

### 图片与视频提示词写作

按 [提示词创作与审阅](../SKILL.md#提示词创作与审阅) 加载对应内置写作 Skill。新编写或获准改写时先读 `writing`，需要特定写法时再读 `patterns`，示例按需。同一请求复用已读章节。仅搭建工作流或只写提示词同样适用。用户指定其他 Skill 或写法时按其要求，原样保存或执行时保留用户给定的正文。

图片按 [图片提示词编写与审阅](../../ouo-script-to-film/references/image-prompts.md) 核对静态可见状态、构图、材质、准确文字、视图数量和编辑范围；视频按 [视频提示词编写与审阅](../../ouo-script-to-film/references/video-prompts.md) 核对动作因果、表演、运镜、时间和声音。一张三视图或九宫格是图内布局，不自动增加生成张数、任务数或报价。

两套提示词正文均不含素材引用标记或绑定说明，素材另按当前画布与模型契约绑定；保存或提交时编译所需真实引用，不删除已有有效原生绑定。工具只返回随包指引，由当前宿主 Agent 按所选依据编写和审阅，不自动改写已保存的提示词。只写提示词时沿用用户已有条件，未指定的时长、画幅、模型或配乐不套默认；准备实际生成时再按当前契约补齐必要选择。旧服务缺少指南工具时仍可使用宿主可用的写作 Skill，或以随包参考兜底，如实说明实际依据。本地 Skill 不替代媒体工具，也不切换生成器。

### 视频控制条件筛选

用户未指定视频模型且明确提出首尾帧、视频参考、原生声音、时长或比例等要求时，调用 `recommend_video_models`。将实际要求分别传入 `mode`、`needs`、`duration_seconds`、`aspect_ratio` 和 `resolution`；`task` 保留创作目标，但工具不从这段文字推断控制条件。没有素材也可先比较入口，不能为筛选编造素材地址。只需要列模型时仍用模型目录，用户已指定模型时直接读取该模型的参数。

这项推荐比较当前账户目录声明及实际 Schema 字段，不是视频画质排名。候选全部保持 `review_required`；`accepted_by_schema` 只代表该字段通过结构检查，`explicitConstraints=false` 表示 Schema 没有明确限制这个取值，不能据此声称业务支持。跨字段 `rules`、素材归属与可用性尚未检查。按照候选的 Agent 描述和用户任务解释选择，不把目录顺序或控制条件匹配说成角色一致性、运动或画质优胜。选定后读取完整参数契约并预检实际候选参数。无候选时如实说明冲突，不能悄悄改变时长、模式或声音需求。

## 创作模板

用户希望从原创短剧、原稿改编、连续角色、商品宣传、参考驱动视频、配音音乐或拉片提取开始时，可调用 `search_creation_templates`，用简短任务关键词搜索，再用返回的精确 `templateId` 调用 `get_creation_template`。模板为当前宿主 Agent 提供输入要求、步骤与检查点，按用户已有资料执行相应步骤；不要求用户先阅读模板说明。当前可用七类，声音和分析模板连接真实契约准备与已有任务查询；未接通任务执行时按明确阻塞停止，不改用图片/视频工具或直接调用其他 API。仅使用当前目录可见的模板，不使用历史 templateId 绕过限制。

模板提供创作步骤建议，搜索和读取本身不创建草稿、修改剧本或提交任务。遵循当前用户要求与授权边界；后续有明确创作需求时才保存创作草稿，方案确认与付费确认仍分开。找不到合适模板时直接按用户任务创作，不为匹配模板改写用户目标。

## 工作流

默认先创建并保存画布节点，再生成。确定当前授权内的准确项目；缺少目标时使用原生项目选择入口，不将普通生成自动降级为独立任务。提交请求使用 `execution=canvas`（默认值）及 `canvas.project_id`、稳定的 `canvas.request_id`；修改已有节点还须使用该节点准确的 `node_id` 和 `expected_edit_revision`。只有用户明确要求“直接生成图片/视频”等不使用画布的方式时，才设置 `execution=direct`，且不传 `canvas`。保留当前工具契约；旧服务没有该能力时，说明当前无法在画布中开始生成，本次未提交生成；节点是否已保存按实际回执说明，不自动改用独立任务。

1. 复用当前请求已核实的 OUO 用户和空间。缺少身份信息或授权刚恢复时才使用 `get_account`；后续真实报价本身会读余额，不为重复检查余额增加调用。
2. 用当前空间的 `list_models` 和 `get_model_parameters` 选择模型、读取契约并预检候选 `model_param`。已有本次请求的目录和匹配模型契约时直接复用；模型、用途或模式改变，或服务明确报告契约失效时再读取。没有项目或草稿也可以选型。只读能力地图、诊断和模板选择不作为普通生成的额外前置步骤。不要猜模型名、参数、素材地址或供应商字段。
3. 缺少会影响生成的参数时，使用 `ask_followup_questions` 收集补充信息。选项来自模型 Schema 或用户已有素材。返回 `answered` 时直接使用答案，仍待回复时按相应交互方式等待。
4. 参数完整后，显式直出且当前 schema 支持顶层 `request_id` 时，先为新意图生成并保留一个稳定标识，费用确认、提交和恢复均带原值；同标识改参会冲突。再调用 `show_generation_confirmation`，它会读取真实预估报价并展示参数、`requiredPoints`、`availablePoints` 和 `affordable`。图片、视频的最终费用可能按实际返回数量、时长、token 及业务规则重新结算，可能高于预估；报价不是最终扣费上限。展示卡片本身不代表用户同意；结束当前回合，等待用户明确确认准确请求及实际结算说明。用户在卡片中修改默认参数、更新报价后点击“确认生成”或“确认全部”，这次真实回复已确认最终参数和费用说明；以最新 `ouo-generation-approval-v1` 的 `request/quote` 或 `ouo-generation-batch-approval-v1` 的 `items[].request/quote` 为准，替代初次工具调用中的参数。不要因为这些已确认的编辑再次询问、索要截图或重开确认卡。只有确认之后又变更了请求或需接受新的报价时，才重新确认；仅有上下文更新仍不是用户确认。宿主不支持卡片时使用 `quote_generation`，明确披露实际结算可能更高后在对话中确认。
5. 收到上述真实确认回复后，沿用最终请求中的执行方式、画布目标、素材引用及原幂等标识，原生调用一次 `submit_generation`；批量确认按最终清单逐项提交，无需逐项再问。画布模式由服务先保存并独立回读目标节点，再提交生成；保存失败或不明时停止生成。旧服务的无标识直出不具备本地去重，不能在受理未知后重试。保存返回的业务 `taskCode`、`submissionRead`、`canvas` 绑定及 `attachmentRequest`。提交工具自动打开进度卡，无需再调用 `show_generation_progress` 创建重复卡片。卡片自动查询同一任务、展示实际排队和预计时间；失败、取消或结果就绪后停止轮询。任务成功但结果地址尚未返回时，卡片有次数上限地继续读取原任务，随后可以手动刷新；不重新生成。后台查询、回执恢复或宿主明确不支持卡片时，使用只返回数据的 `get_generation_task` 查询同一个 `taskCode`；旧服务缺少该入口时按实时契约说明回退方式。
6. 需要找回任务时调用 `list_generation_history`；只有 `resultReady=true` 且存在 `resourceUrls` 时才报告生成完成。
7. 当前卡片在结果就绪后自动展示媒体，`get_generation_task` 仅查询数据，不打开卡片。只有用户要求重新查看或已确认原卡缺失时，才调用一次 `get_generation_result` 或兼容入口 `show_generation_result`，传入同一个 `task_code`；两者选一，不再追加展示。组件已经展示图片时，回复简短说明即可，不要再次把原始网址嵌入 Markdown 造成空白图片卡片。只有宿主明确不支持组件时才提供原图链接；不要为展示结果重新提交生成。
8. 用户明确要求停止且任务仍可取消时调用 `cancel_generation`，随后重新查询同一个 `taskCode` 确认最终状态。

画布模式提交后，按 `canvas.taskState.persisted / presentOnCanvas` 判断原业务任务号和生成态是否已写入。任务受理、卡片展示与结果写入分别按回执判断。

`canvas.completion.automatic=true` 时，服务端沿原授权查询同一任务，回填原节点并独立验证，关闭画布、预览卡或结束回合后也可继续。由服务处理 `pending`、`retrying`。需要核实进度或落图时沿原 `submissionRead` 查询，以 `canvas.completion` 判断结果。授权等待时恢复原授权，阻断时按实际原因处理，保留已生成结果及协作者修改。

旧回执未启用自动完成且已有明确受理时，按需使用原 `stateSyncRequest` 恢复状态保存。仅在原结果已就绪、确需手动回填时使用 `attachmentRequest`，以独立回读核实原节点。受理未知或保存结果未知时沿原回执核对，保留原请求和操作标识。制作运行仍走其独立的有界推进流程。

支持的原生控件在生成前按准确模型与前端参数规则保存并回读；查看 `canvas.generationControlsApplied / generationSettingsApplied` 及 `generationSettings.pendingParameters`，控件同步与全部显式参数同步分别核验。额外参数、媒体参考或旧版回执仍可能未同步，缺少证明按未同步处理；原生成请求保留准确参数，不能宣称重新生成已绑定待处理字段，也不为补齐控件换标识重提旧任务。

数量贯穿整个意图核对：单张适配不支持更多产物时说明限制，不额外生成候选或把多张默认为一张。若按用户原数量分次执行，每项仍须有匹配的费用确认或有效授权，并统计实际成功输出；部分完成时只处理未完成且明确未受理的项，不能补跑受理未知项。

## 对话内交互

表单支持单选、多选、文本和图片或音频选项，每次最多三个问题。媒体地址必须来自已配置的 HTTPS 媒体域；没有可用媒体时使用文字选项。用户已提供的参数不再重复询问。

用户提交消息中的 `formId` 或 `confirmationId` 用于关联当前卡片。表单答案、跳过和换一组选项只补充需求，不能视为生成授权。只有当前确认卡对应的明确用户确认消息才授权提交其 `request`；组件上下文更新或工具返回的 `awaiting_user` 状态不代表确认。已处理的确认消息不重复提交。

取消卡片或点击“暂不生成”后停止该请求。发送失败时可以继续接受用户在对话中的明确回答；发送状态未知时先检查是否已有对应回复。进度卡取消按钮需要再次点击确认，取消申请成功仍要以随后读到的任务状态为准。

## 查看已有结果

用户要求预览、查看或重新展示已有图片或视频时，直接读取已有任务，不执行生成工作流中的模型查询、报价或提交步骤。已提供 `taskCode` 时调用 `get_generation_result`；未提供时使用 `list_generation_history` 找到对应任务，无法唯一确定时再请用户选择。

`get_generation_result` 或兼容入口 `show_generation_result` 会打开已有任务的结果卡，选择其中一个入口即可，不再追加展示调用。后台状态查询和回执恢复使用 `get_generation_task`，只返回数据，不打开卡片。已有卡片显示时继续使用原卡；仅在用户要求重新查看或确认原卡缺失时重新打开。结果卡自动更新至 `resultReady=true`，查看和刷新已有结果不会重新生成或扣费。对于此前已确认生成成功的任务，不因图片显示失败而重新提交。

## 预览验收与回退

提交、任务查询、结果查询和展示工具使用当前对话的原生 OUO 工具。`get_generation_task` 只返回任务数据；展示入口返回预览组件，仍须核实宿主实际显示。从外部命令行、临时 MCP 客户端或独立 app-server 读取结果，不等于在当前聊天中展示了组件。不要把后台调用成功、资源可读取或独立网页截图当成 Codex 聊天预览通过。

如果当前对话没有加载原生 OUO 工具，先检查宿主可用的工具发现、连接状态和明确错误，按上面的授权状态处理。工具目录未刷新时使用实际可用的宿主刷新入口；确实只有新对话才能加载目录时再说明宿主限制，不把新建聊天或重启应用作为通用修复。恢复后继续原来的查询。已生成的任务复用其 `taskCode`；不在后台重新提交生成，仅显示问题不要求用户重新登录。

对于用户已经反馈无法显示，或已确认带有 `Content-Disposition: attachment`、`x-oss-force-download: true` 的结果地址，不再重复输出 Markdown 图片占位。只有确认宿主已展示组件，才能说明预览已显示；无法展示时说明当前无法在聊天中预览，原文件链接只能作为下载入口。不要下载远程图片来绕过宿主显示限制。

## 失败与重试

- 有 `submissionRead` 时先按原样只读查询；也可使用当前已声明的 `get_generation_submission`，画布模式带原 `canvas.request_id` 和准确 `project_id`，直出带原顶层 `request_id` 且使用同一授权范围。`submitted` 仅表示已有受理，按返回的 `taskRead` 读取；`submitting / unknown` 继续核对原任务，`rejected` 只说明原提交明确拒绝，均不授权重发；`preparing` 仅可在原确认仍有效时继续原准备。
- 收到 `SUBMISSION_UNKNOWN` 时不要自动再次提交。回执缺失或旧服务没有只读入口时，使用业务任务历史或同一个 `taskCode` 恢复状态；无标识直出没有本地回执，不换 ID 或换入口试投。
- 画布保存不明时保留原 `canvas.request_id` 与操作标识，先读取原保存；只按原操作明确允许的恢复方式继续。相同请求重放恢复原任务，不能换标识逃过冲突或受理不明保护。
- 收到 `INSUFFICIENT_POINTS` 时停止提交并告知用户充值或更换任务。
- 收到 `BUSINESS_TASK_UNAVAILABLE` 时只重试查询，不重新生成。
- 仅使用工具真实返回的 `taskCode` 查询对应任务，不以其他执行编号代替。

## 边界

创作草稿的保存、方案确认和生成任务分别核验；草稿请求的幂等或方案批准不能替代生成请求的幂等和费用授权。使用当前 OUO 工具完成模型选择、报价、确认、提交和结果查询，不直接调用其他 API 或绕过账户权限与计费。

使用插件当前配置的 OUO MCP 入口和宿主用户授权。插件版本不能代替工具目录、实际安装和当前聊天加载状态的核验。不要把 Token、用户 ID、空间 ID 或扣费覆盖字段写进 Skill 参数。

空间和可选项目在授权页面绑定。项目目录和画布通过当前工具读取；已绑定项目的授权不能通过工具参数切换到其他项目。切换个人或团队空间、或更改已绑定项目时，引导用户重新授权。当前工具尚不能列举空间或项目域，也不要猜测这些 ID。
