# OUO 剧本到成片

<!-- OUO_PLUGIN_VERSION: 1.0.0 -->

使用当前会话的原生 OUO 工具。先读取实际工具契约；每个工具的实时能力优先于本文。缺失入口时说明对当前制作的影响，并按实际回执报告进度；不能编造任务号、承诺进度已保存或把编排保存称为成片。

用户要先用参考图片或剧本搭建 3D 场景、白模或运镜预演时，按 [本机 Blender](../ouo-blender-previs/SKILL.md) 由宿主直接制作，保存本地工程及已检查预览，直传后导入指定画布。仅建模与导入可独立完成；用户要求继续生成时再进入本 Skill 的模型与费用流程。

制作中收到明确认证失败时，当次按 [授权状态](../ouo-business-generation/references/generation.md#授权状态) 实际发起或加入一次宿主登录，不能只发提醒。该章节统一规定登录入口、系统浏览器、重试及 CLI 兜底。保留原制作、画布、镜头和任务，恢复后先只读核实原状态，不重提生成或恢复已停止的制作。

本 Skill 首次用于当前请求时，先按 [使用时检查](../ouo-plugin-maintenance/references/update-check.md) 执行轻量只读检查；与业务创作共用成功检查 24 小时有效期及提醒记录，自动网络检查总预算最多 3 秒。能力缺失或失败时继续原制作，不在每镜头、生成提交或轮询前重复检查；升级不能恢复已停止操作，也不能作为查询旧任务和恢复进度的前置条件。

所有创作说明遵循 [用户可见输出](../ouo-business-generation/SKILL.md#用户可见输出)；制作受阻时按真实回执说明已完成与待处理的镜头或素材，不向普通用户索要服务源码、部署目录、内部日志或修改配置；未知执行沿原任务核实。

开始执行前阅读 [制作工具与数据](references/tools-and-data.md)，使用其中的真实工具流、对象层级、状态示例和恢复方式。按阶段加载下文的编导与连续性规则。

创建或推进内置角色提取、场景提取和拆分镜前，先用只读制作契约核实对应阶段支持不预消费的 `usage_settlement`。契约缺少该能力时，使用用户允许的 Codex 文本路径或说明当前能力缺口；不能通过准备任务或 `advance_production_run` 探测计费能力。插件版本不能代替实时工具能力核验。

## 默认制作框架

开工前从本次使用的 `get_canvas_editing_contract` 或 `get_production_contract` 读取并应用 `workflowGuidance`，包括 `productionRules`。同一请求复用已读的共用规则，仅搭工作流时也适用。旧服务缺少规则字段时，使用同源的 [共同工作流与制作规则](references/workflow-guidance.md) 补齐并说明版本缺口。下文和各细节参考补充具体操作。准备制作时还要核对实际执行能力和 `compositionLimits`。

开始提取规划、素材规划或搭建画布前，阅读 [剧本工作流框架](references/canvas-workflow.md)。用户没有指定结构时，主动采用以下默认框架，无需让用户重复说明：

**每集剧本文本 → 本集脚本（提取结果、分镜及素材对应关系）；共享角色图 / 场景图 / 道具图 / 角色音色 → 对应的视频分镜 → 本集顺序合成。**

剧本文本和脚本承担原稿及制作索引职责，不连接到视频输入，不把分镜 JSON 或脚本文案作为参考素材。缺少的必要素材建立真实类型的图片、视频或音频占位，再连接使用它的分镜；文本节点不能代替媒体占位。

除用户明确要求不使用素材引用外，工作流视频节点默认必须用 `edit_canvas` 的 `set_prompt` 动作，将本镜所需素材的原生 `@` 引用插到提示词的对应文字位置，传入文字片段与准确 `source_node_id`。仅搭建工作流、素材尚未生成或用户没有主动说“加引用”，均不构成省略理由，也无需为默认引用另行询问。待生成媒体使用原节点的主输出占位，生成回填同一节点后继续解析真实结果。保存后逐个视频节点独立回读正文、引用来源及待生成状态；缺少必要引用时继续补齐，当前契约不支持时说明缺口，不能报告工作流搭建完成。普通“@角色名”、素材连线和另建不相连的结果节点都不能代替原生引用。

每集一个制作组；同一素材建立一次，按实际用途供多个镜头和后续各集引用。用户明确的结构、参考图或制作要求优先于默认方案，保留其未要求修改的现有内容。镜头数、素材数及画布方向由剧本、模型和用户要求决定，不把示意图中的数量或某部剧的设定固化为规则。

搭建或整理节点位置时读取 [画布布局](../ouo-canvas-layout/SKILL.md)，按真实场次、共同引用、用户阅读任务与已有结构形成内容簇，安排共享素材和簇间接续。上述箭头表示逻辑制作关系；局部可用序列、分支或网格，全图构图随内容展开，不固定为按类型分栏或将分镜填满矩形。

制作记录完整保存身份、状态、来源和任务；画布围绕剧本、素材和镜头组织。状态变化不自动新增画布节点或图片任务。脚本使用真实原生字段呈现提取结果与镜头关系；生成提示词保留用户或所选 Skill 的格式，未指定时可用自然语言；模型、时长、比例等使用参数控件。

短剧新建或明确改写的共享角色图默认为**纯白底、16:9、同一角色的正面 / 人物左侧面 / 背面全身三视图，合为一张**；共享道具图默认**纯白底、1:1、物件完整居中**。这两类素材的比例独立于成片画幅，实际生成参数须按实时模型契约显式保存并回读，不能只在正文写比例。场景图与静态分镜按各自需求处理，用户明确规格优先，已有准确素材继续复用；详见 [素材图规格](references/canvas-workflow.md#共享素材图规格) 和 [图片提示词](references/image-prompts.md#短剧共享素材规格)。

## 阶段执行能力

Codex + Skill 可以完成分集、实体提取、拆分镜、素材关系和提示词等文本工作。图片、视频、声音生成及整集渲染需要宿主真实提供相应工具、参考素材输入、费用授权和可核验的产物回传；Skill 本身不提供这些能力。不能把可发送消息或调用 MCP 工具当作宿主具有媒体生成能力。

读取制作契约的 `engineOptions` 按阶段选择，新文本执行选择使用 `host`，表示当前宿主按 Skill 创作并保存结果。当前 OUO 阶段执行器尚未接入宿主媒体工具，图像、视频、声音和合成只支持 `builtin` 或 `auto`，对用户统一称“OUO 生成服务”；这些媒体阶段的自动模式也使用 OUO 服务。不能选择 `host` 后暗中提交 OUO 媒体任务。历史 `codex` 值按契约兼容，旧记录和回执保留原样；旧记录中的不支持选择保留供用户调整，已受理任务继续查询原回执。

用户明确指定宿主工具时，先核实对应媒体能力和结果回传路径；未接通就保留需求并说明具体缺口。宿主已经生成的真实图片、视频或音频可通过原生上传登记、素材绑定复用，这不代表整个制作阶段已接入。成片核对同样以真实查看、播放或媒体信息工具为依据，只记录已经检查的项目；未检查的画面和声音不能标为通过。

## 开始与恢复

进入整集制作、拆分镜或搭建工作流前，先按 [制作规格](references/canvas-workflow.md#开工前制作规格) 一次收集缺少的关键选择：成片横屏/竖屏及准确比例、视频模型（允许混用）、各模型当前模式和可用时长。仅搭工作流同样需要这些选择；“自动完成”不表示用户已选择成片画幅或模型。沿用用户已明确的选择，不擅自默认成片为 16:9、某个模型或统一 15 秒。角色与道具参考图采用上述独立素材规格。先读实时模型契约，再拆叙事小镜头并按各镜模型组织生成片段。独立编写或改写提示词按对应写作指南处理，不为缺少制作参数强制追问。

下一步依赖画幅、模型、项目、素材或费用选择时，合并必要问题，展示对应原生表单或确认卡后立即结束当前回合。等待期间不继续命令、工具、轮询、长篇说明或再开一张卡。收到用户实际回复后，沿原制作、运行、表单及准确版本继续；不把卡片送达或上下文更新当成回答，不自动推进已停止的制作。仅查看进度且原授权允许继续时不必等待。

1. 按 [项目定位与选择恢复](../ouo-business-generation/references/projects.md#项目与具体画布定位) 核验用户给出的目标；已指定项目/画布空间及画布名称时，按真实目录逐层核对，唯一匹配后直接定位，不重复要求点卡。未指定目标时打开原生项目选择卡并等待。用户明确反馈卡片未出现时，沿该参考恢复真实目录或文字选择，保留先前指定的画布名，不循环要求去缺失的选择器操作。使用用户提供的剧本或已授权项目中的原稿。需要本地素材时打开原生上传卡，等待用户实际选择文件和上传。
2. 查找已有制作记录并恢复，避免同一剧本重复创建整套镜头。新建时保留完整原稿、来源和版本，长剧按集/场景分批提交，不截断原稿。已有记录的修改带准确版本及稳定 request_id。
3. 展示制作卡：已选择的画幅比例、视频模型及混用分工、各模型时长限制、分集范围、阶段执行方式、素材需求和费用模式。支持 `preferences` 的服务将比例与准确模型名持久保存；旧契约保留到制作说明，按实际回读说明哪些比例或模型尚未同步到生成设置，以及对下一步制作的影响。参数选择不产生费用授权。
4. 从持久记录执行当前可继续步骤。每一步完成后保存输出和来源。换执行方式时保留实体、状态、镜头 ID 与可复用结果。

## 编剧与导演

按 [编导规则](references/directing.md) 进行分集、提取和分镜。开始实体提取、两层拆镜或提示词改写前，阅读 [制作规则](references/production-rules.md)，核对发声归属、素材设定、对白保护和时长。忠于原稿，新增设定标记为创作决定；未确定的关键内容不能伪称原稿事实。Codex 可以直接产出结构化内容；用户选择 OUO 生成服务时使用实际可执行的业务入口。OUO 角色提取、场景提取和拆分镜不做积分预消费，先提示按实际 token 扣费、金额未知，再取得逐任务确认或有效静默授权；不将零价推断为免费，不绕过当前工具的费用流程。

每集形成完整剧情单元。镜头包含可拍动作、对白、时长、空间关系、切入/切出理由及原稿出处。角色、场景和道具使用稳定实体引用，不用同名字符串代替身份。对切镜连贯性和实际生成结果分别检查。

逐镜根据动作数量与难度、人物调度、对白语速、必要停顿和运镜估算时长，再选当前模型与模式支持的秒数。原生参数返回的 `defaults.duration` 只用于节点初始化；搭建工作流时用本镜规划时长覆盖，并按 [内容和参数](references/canvas-workflow.md#内容和参数) 独立回读核对。

交叉剪辑或插入闪回时，为该集每个镜头填写唯一 editOrder；shot.order 只在场次内排序。按同一剪辑方案排列分镜与合成片段，不按故事时间重排剪辑。

交付可生成的工作流或开始生成前，将实际完成的原稿保真、镜头连贯性、切镜、轴线、状态、对白、节奏或提示词审阅追加到 editorialReviews。按 [制作工具与数据](references/tools-and-data.md) 绑定准确的已保存版本、审阅范围与工具返回的 `inputDigest`；后续修改使记录成为历史时，重新核对有关内容。提示词审阅依据用户目标、已读取并应用的写作 Skill 与实时模型契约，证据指出具体内容和问题；用户明确选择其他写法时按其依据审阅。参数和引用核对也不能单独代替写作检查。审阅不授权改写用户给定正文，不代替真实媒体检查，也不产生费用授权；沿用用户已选的自动完成方式，无需为每轮文字审阅再次请求确认。

## 状态和素材

按 [连续性与素材](references/continuity.md) 创建状态版本。先解析进入状态，再应用本镜头事件得到离开状态。明确故事时间、分支和继承来源；闪回不能继承剪辑顺序中的未来状态。

两条平行剧情会合时，用 stateSources 分别引用角色、场景、道具的来源镜头；不能只手写最终 stateIn，从而丢掉前置事件与后续重做的关系。

优先检查用户上传和可用素材库。先区分连续性状态、需要独立参考的视觉变体与画布节点，再准确绑定实体、状态和参考用途并跨镜头复用。只有镜头确需新的视觉参考时，才让用户上传或在授权后生成；不能为每集、每镜头或每条状态重复生成角色标准图。没有准确素材时保留缺口，不能用相似名字的素材冒充，或用旧状态素材伪装新状态。

每个角色分别保留自己的音色音频入口，包括旁白、OS 和仅发声角色；同名人物按稳定身份区分，不能共用默认音色冒充已经选声。按 [角色音色与引用](references/canvas-workflow.md#角色音色与引用) 保存音色来源、真实声音标识和发声镜头。外观变体不自动改变音色；只把本镜实际发声者的音频连接到分镜。占位不等于已有音频，音色及语音生成仍需对应费用授权和实际模型能力。

角色和场景的变体默认以各自第一张已确认的基础图为母图走图生图，将真实母图媒体传入模型参考参数，并保留派生来源。角色换装、年龄或形态变体保持身份依据；场景日夜、布置或损坏变体保持空间依据。已有准确变体直接复用；缺少母图先补齐基础图，模型不支持时说明限制，不静默改为独立文生图。用户明确指定其他参考或制作方式时按其要求调整。

默认使用多参考视频生成：按镜头选取角色、场景、道具及其进入/离开状态的准确素材，直接传入支持多参考的实时模型契约。素材齐全即可生成视频，不创建逐镜头首帧图或图片前置任务。图片生成用于补齐缺失的共享实体/状态素材或用户明确要求的静帧；首尾帧模式仅在用户明确选择或确有镜头要求时采用。用户指定的模型不支持当前多参考需求时，说明差异并提供可用选择。

新编写或获准改写图片和视频提示词前，默认按 [随包完整指南与版本规则](references/prompt-guides.md) 读取对应 `writing`；MCP 的同一 Skill/契约版本不低于随包版时可调用 `get_image_prompt_guide` 或 `get_video_prompt_guide`，否则使用随包完整章节。三视图、复杂编辑、多镜头等需要具体写法时，再按 [图片提示词](references/image-prompts.md) 或 [视频提示词](references/video-prompts.md) 读取同一依据的 `patterns`，示例按需。同一请求复用已读章节。仅搭建工作流时同样适用。用户明确指定其他 Skill 或写法时按 [提示词创作与审阅](../ouo-business-generation/SKILL.md#提示词创作与审阅) 读取和应用，原样保存用户正文时保留原文。保留所选方法的风格和格式，不把内置示例作为唯一标准。视频正文在切镜、反打、再次入画与关键交互处就地复用准确引用，开头的对应表不能代替后续指代；同段指代清楚时不逐词重复。画布原生引用、模型标签及真实媒体按各自实时契约绑定和编译。保留图像与视频各自的 `stagePrompts`，同步对应脚本的 `shotPrompt`、`motionPrompt` 和节点。模型专用参数保存在对应阶段 `modelParam` 并独立回读。实际完成的审阅写入 `editorialReviews`，生成画面另行验收。

对白和镜头应有明确对应。采用内置默认写法时，可在相应时间段连贯描述原句、机位和表演；用户或所选 Skill 使用声画表、台词轨或模型结构化格式时保留，只核对说话者、实际原句、时间与画面关系及模型支持情况。分列不等于不合格，不强制读内置对白示例，也不以审阅为由重写用户原文。

真实产物的检查证据追加到 reviews，并绑定准确 outputId 和查看时的 productionVersion；不要修改镜头描述来记录验收结论。旧产物失效或更换后重新检查对应新输出。

## 制作和交付

先保存制作记录，再按默认框架或用户定制方案搭建画布。长剧先用一集核对节点职责、素材复用、分镜对应和布局，再沿用结构扩展；没有未决选择时不逐集重复询问。按当前工具契约选择能实现该结构的原生编辑入口，不直接将整份制作图展开为节点。镜头、参考素材和结果之间使用真实可执行引用；画布连线与任务依赖分别核验。分批保存并读回准确操作记录，不要求用户逐个进入画布点击。

有报价的付费任务先读取真实报价；角色提取、场景提取及 storyboard 阶段的拆分镜使用 usage_settlement，提示按实际 token 扣费，不要求预消费报价，也不填写虚构金额。只有用户真实确认或服务端仍有效的费用授权才能执行；Skill、剧情确认和上传都不是付费许可。未知费用的逐任务确认绑定当前步骤和参数、无自动重试；也可沿用不设金额上限的“静默执行（按业务扣费）”。后者使用 backend_balance，仍受执行计划、阶段、模型、有效期和重试次数约束，按账户余额及实际费用结算；余额不足保留进度，充值后继续。不得调用 app 专用确认工具代用户点击，不将预估费用或当前余额描述为最终扣费上限。

提交及恢复保留原请求和任务身份。超时、未知受理或重启后查询原任务，不能换请求 ID 重提。等待过程中保存进度；用户停止时停止调度并按现有接口处理进行中任务。

新的媒体步骤先保存并独立回读目标节点，再进入生成提交；已有素材占位时，在实时步骤契约支持的 `canvasTarget` 中填写该节点及当前 `editRevision`，首个结果回填同一节点，回填失败继续恢复原操作。省略目标会创建新节点，不能把这种新建称为原占位已更新。任务成功、画布保存和下游引用解析分别核验；`generationSettingsApplied=false` 时不得声称原生参数控件已完整同步，详见 [内容和参数](references/canvas-workflow.md#内容和参数)。

当前整集制作仅按已保存镜头顺序调用 `video_merge` 拼接片段，读取真实结果并检查播放、源片段音画、接点与首尾完整性。不自动选片、重剪、添加转场、字幕或音量混合。对白、配音、音乐按已有镜头和用户选择处理，不擅自补充收费任务；额外字幕或高级规格超出当前能力时说明限制并保留要求。交付可播放成片和对应每集画布组，明确仍待核验的项目。

合成完整覆盖该集镜头并遵循已保存剪辑顺序。媒体来源核验、旧任务回执恢复、秒转帧及当前渲染限制按 [制作工具与数据](references/tools-and-data.md) 执行；不把任意 URL 或手写成功记录当作有效产物，也不忽略暂不支持的字幕和规格要求。
