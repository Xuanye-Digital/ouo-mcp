# 视频提示词编写与审阅

本文提供镜头视频提示词的默认写作方法与保存约定。先按 [提示词创作与审阅](../../ouo-business-generation/SKILL.md#提示词创作与审阅) 加载默认内置写作 Skill 或用户明确指定的方法；结合 [编导规则](directing.md) 和 [制作规则](production-rules.md) 中适用于本次任务的约束。媒体生成使用当前真实工具。

## 内置写作 Skill

新编写或获准改写视频提示词前，按 [随包完整指南与版本规则](prompt-guides.md) 选择并读取 `writing`。当前 MCP 同一 Skill/契约版本不低于随包版时可用 `get_video_prompt_guide(params={"section":"writing"})`；缺失、旧版或读取失败时使用 [随包视频 writing](prompt-guides/video/writing.md)。常规单镜头可直接写作，多镜头、续接等需要具体写法时再读同一依据的 `patterns`，示例按需。仅搭建工作流、只写镜头提示词时同样适用。用户明确指定其他 Skill 或写法时由宿主读取和应用，原样保存用户正文时保留原文。同一请求复用已读章节，成稿按实际任务审阅。

先确定这是新画面、改写压缩、单镜头、多镜头、续接、循环还是局部编辑。围绕起始状态、一个主要事件和最终落点组织正文，明确人物站位、持物与接触关系，把情绪落实为目光、呼吸、手部或身体变化。主体动作、机位运动、变焦与焦点转移分别写清；时间能容纳动作、原句对白及停顿。续接继承结束状态，循环闭合位置、姿态与运动相位，局部编辑限制修改范围。压缩时保留有效的全局视觉、高清、真实感与约束信息，合并重复要求和整段复述，去掉无关禁词。

只编写或改写提示词时，缺少模型、画幅或时长不成为强制追问理由，不套示例默认值；进入下文的 OUO 制作和生成准备时，另按当前制作与模型契约收集必要选择。正文按用户格式交付；未指定时给简短全局要求与动作正文，已知时长且有多个节拍时默认写连续秒段，一镜到底也适用，切镜另明确。简单持续动作可用一段文字，未知时长不编造秒数，不夹分析、自评或空模板。声音规则不默认添加字幕、配乐或禁用配乐。

视频正文允许并按实际画面使用素材引用，保留用户或所选 Skill 的格式。画布视频节点默认包含本镜所需素材的原生 `@` 引用，只有用户明确要求不使用素材引用时才省略；待生成素材也按下文规则先引用。开头的对应表不能代替分镜正文：切镜、反打、再次入画及关键交互处，重新在具体主体、道具或声音旁引用同一准确来源。画布和模型标签按各自当前契约编译、核验，不删除有效引用或把手写标签当作真实绑定。返回的 `integrationRules` 与下文说明 OUO 素材和保存方式。旧服务无该工具时仍可使用宿主适用的写作 Skill，或以本参考兜底，如实说明实际依据；不能编造已读取服务端规则。

## 先建立镜头依据

读取本镜完整原稿、已确认参考、进入/离开状态、前后切点及用户已选画幅、模型和生成模式。确认当前契约的时长、参考字段、多镜头和音频能力。缺少画幅、模型或关键事实时补齐选择；不边写提示词边默选模型。

按叙事目的确定本镜要让观众看见的变化，再拆成可执行动作。不要用“展示一段紧张的故事”“人物很悲伤”“高级电影感”代替可见行为；写明视线、手部动作、停顿、空间位置及结果。每个片段控制在模型可表达的动作和切镜数量内。

## 逐镜写作

采用内置默认写法且用户未指定格式时，可按以下信息组织成连贯的导演描述；用户或所选 Skill 定义了其他写法时沿用其结构，不把这些项目当成必须齐全的栏目：

1. **开场构图**：景别、视点、人物与场景位置、朝向、视线或运动方向。依据实际横竖画幅安排主体和空间，避免重要动作出画。已确认的角色外观和场景保持冻结，只点明本镜必要状态。
2. **动作节拍**：谁先做什么，对方如何回应，物件如何移动，动作最后停在哪里。已知时长且有多个动作、反应或对白时默认按连续秒段描述，一镜到底也划分节拍。主画面时间线从 0 覆盖到已选时长，检查空缺、倒序及意外重叠；不同声画层的并行时段可明确重叠。集内剪辑时间与片段内部时间分开，正文与参数时长一致；简单持续动作可直接描述。
3. **镜头语言**：写明固定机位、跟随或推拉的起点、路径、终点以及对焦对象。一次运动有明确表达目的，避免同一时刻既固定又环绕、极近特写又全景等冲突。模型支持多镜头且剧情确需时才明确切点；否则保持单一连续机位或拆成多个生成片段。
4. **表演与声音**：把情绪落实到可见表演，对白按原稿逐字保留并指明说话者。OS、旁白、内心独白和画外音不改成角色开口，标签不进入实际播放文字。环境声、动作声写明来源和起止；模型不支持对应声音时保留独立声音计划，不在提示词里许诺已合成声音。
5. **光线与结尾**：沿用场景事实，写清对动作有意义的明暗/光源和最终画面，给后镜保留动作、视线和声音接点。不得为美化画面新增天气、角色、道具或故事事件。

模型名、画幅、分辨率、生成总时长、音频开关放在真实参数控件和 `modelParam`。秒段描述属于片段内部导演信息，不能代替参数。参考素材通过当前模型的真实字段传入；只写“参考图片”或画一条连线不算绑定。契约要求的参考标签、分段格式或 `multi_prompt` 按真实接口编译，实际编译参数须保存到对应 `stagePrompts.generate_videos.modelParam` 并审阅，生成请求必须与已保存版本一致。创作 `text` 保留用户或所选 Skill 的格式及有实际依据的就地引用，不混入内部 ID、原稿索引、状态补丁或任务管理数据；画布标记不能原样充当模型标签，结构化模型输入按真实字段保存。

对白与实际画面有明确对应即可。默认可把原话、机位和表演写在同一时间段；所选 Skill 采用声画表、台词轨或模型结构化格式时保留其写法，核对说话者、原句、时间和画面关系，不因分列判不合格。跨切镜的对白说明声音延续，贯穿环境声可统一概述。检查实际台词是否缺失，而非按某个词或固定句式机械判定。

保留用户与所选 Skill 的风格选择。按本次任务指出具体的事实或约束冲突，不因偏离内置示例、使用不同修辞或栏目而改写。新编写正文时用具体内容落实创作目标，示例仅供需要时参考。

原稿和脚本索引不接入视频参考区。视频默认引用本镜需要的真实媒体节点，空媒体保留待生成槽；连接后用 `set_prompt.parts` 将准确来源引用插到对应文字位置，`kind=reference` 指定 `source_node_id`、`media_kind` 和主输出 `output_index=0`。仅搭工作流或素材尚未生成时也完成此步骤，不等待用户主动要求引用。生成完成后沿用原标记解析结果，不把普通“@角色名”或脚本 JSON 当成引用。逐一核对发声者的独立音色及真实声音输入，外观参考不能代替音色，未发声角色不占本镜音频参考。

画布编译提示词的每个引用必须写清主体与用途，按 [角色音色与引用](canvas-workflow.md#角色音色与引用) 逐项指代，并把引用放在实际使用的句子里。同一来源在后续分镜再次使用，就再次传对应 `reference` 片段，复用原节点；不要只在开头写“人物外观”等类别后堆放素材。同段指代清楚时无需逐词重复，压缩时保留消除歧义的重复引用。模型标签和媒体输入按所选模型契约对应核验。

多参考先明确分工：图片提供指定身份、物件外形或空间视角；视频可以只提供动作、节奏或运镜；音频可以只提供某位发声者的音色。按实际需要限定采用哪些属性，不能将原视频的人物、产品、文字或声音一并带入。同一角色或产品的多视图不增加实体数量；外观依据不代替当下站位、持物与衔接状态。

首帧模式要求 `adaptive` 时，用该帧真实媒体的宽高核对目标画幅，保留模型规定的自适应参数；不能把画布节点尺寸当成图片尺寸。短模型和长模型混用时，分别给每个片段保存可用时长及相应动作节拍。

图像提示词描述静态画面，按 [图片提示词编写与审阅](image-prompts.md) 执行；视频提示词描述随时间发生的动作，分别保存到 `stagePrompts.generate_images` 和 `stagePrompts.generate_videos`。不把静态立绘描述当视频提示词。

## 全局视觉与负面约束

按题材选择媒介、画质与成像方向、光线色彩、材质细节、空间连续性、声音和文字要求，全局写一次，局部例外放在对应节拍。高清、8K 质感、真实摄影感或电影感可保留，再用本镜可见的纹理、照明、层次与运动支撑；不把所有通用描述当作冗余。正文出现 8K、HDR 或帧率不等于真实规格已设置，实际参数按模型契约保存与回读。

先写目标状态，再选本镜易错项作为负面约束，例如交接时道具不复制、不提前换手，移动不逆向、站位不跳变，表演不跳过发现过程，画面不扭曲或闪烁。对白、环境声、动作声与配乐分别安排；无字幕与保留原有产品标识可以同时成立，但须限定新增文字。写实、禁 CG、无字幕、无配乐均不作为所有任务的默认要求。

正文可用自然语言说明“不要”“禁止”或“保持”；独立 `negative_prompt` 参数只在当前模型契约支持时使用，不从历史数据推断本次可用字段。正负描述逐项核对，不能要求手部操作又禁手、展示标识又禁一切文字、三维动画又禁 CG。局部编辑明确修改范围和保留范围，不用长串通用禁词抵消正向描述中的矛盾，也不把字体透明度等未确认写法当成控制能力。

## 示范

以下是为说明写法虚构的 12 秒镜头，使用前必须以真实剧本和所选模型契约替换，不能加入用户故事：

> 旧宅门口的双人中景。人物甲在画面左侧面向右，人物乙在右侧面向甲，门框保留在两人身后。沿用已确认的人物和场景参考。0–4 秒，甲低头将右手的钥匙递到两人之间，乙看向钥匙，伸出左手。4–8 秒，镜头缓慢推近到两人的手，乙接稳钥匙后甲才松手，钥匙留在乙左手。8–12 秒，镜头停住，乙收回左手，甲的空手自然落下，留出收势。门外雨声持续，交接时有一声轻微金属碰响，无对白。门口原有灯光保持不变，结尾不切到新场景。

写作依据是清楚的交接顺序、手与物的位置、单一镜头运动、可生成节拍及稳定的离开状态，不是增加形容词。真正需要对白时使用原稿原句，不能照抄此例的“无对白”。

对白写法示范，同样为虚构的 12 秒片段，人物、台词和参数不进入用户故事：

> 旧宅门口，甲在左、乙在右，两人隔一步面向彼此。0-6 秒，双人中景，甲将右手的钥匙递向乙，先看一眼钥匙，再抬眼看乙，轻声说：“钥匙交给你。”乙的目光随钥匙移动，伸出左手接稳，甲才松手，空手落回身侧。6-12 秒，沿同一轴线切乙近景，乙将钥匙握在左手中，短暂停顿，看着甲平静地说：“我在这里等你。”说完仍保持目光。门外雨声持续，交接时响起轻微金属碰声，门口灯光保持不变。

对白、表演和机位在对应时间段内共同发生；不会先列“甲说原句、乙接话”，再把两句原话附在文末。

## 独立审阅与保存

对新编写或获准改写的内容，按用户目标、所选写作依据及模型契约核对实际问题；以下项目按任务适用，不能以模板或示例相似度替代判断。只原样使用用户提示词时保留正文，发现实际契约问题再说明：

- 盲读提示词能否重建开场站位、动作因果和结尾画面；主体、机位和运动是否互相冲突。
- 所有口述与原稿逐字对照，说话者、语种、OS/旁白类型和顺序未变化；朗读估算连同停顿能放进片段。
- 对照实际台词，确认所选格式中的说话者、原句、时间与画面明确对应；声画分列同样可以满足。台词跨切镜时，声音延续和画面反应有明确对应。
- 本镜实际模型/模式支持所选时长与参考，长短模型混用时分别核对；不把所有镜头套同一个上限，不靠删对白凑时长。
- 已知时长的多节拍片段有连续时间分配，一镜到底没有因分段而误切镜；正文、主时间线与实际总时长一致，声音重叠有明确归属。
- 前镜结尾到本镜开头的手势、物件、轴线、服装、伤势、空间和声音接点有依据，未把未来状态带进闪回。
- 没有新增故事事实、未确认参考或管理字段；全局视觉要求与当前题材相容，风格有具体依据，负面约束不误禁必要内容，画幅中的关键动作可见。
- 脚本 `motionPrompt`、视频节点和模型请求来自同一已保存正文版本；节点原生引用与模型专用格式按契约编译后分别核对，静态 `shotPrompt` 保持独立。未实际生成不能声称产物符合提示词。
- 除用户明确要求不使用素材引用外，逐个回读视频节点提示词并核对本镜所需原生引用和来源，包含待生成媒体；缺少必要引用时继续补齐，能力不支持时保留未完成项，不能判工作流搭建完成。
- 略过开头的素材对应表，按已保存正文的镜头、时间段或动作句检查入画、关键操作和发声旁是否有应有的引用。逐处核对来源和用途，音色跟随发声者且放在台词引号外。只在开头引用时，即使节点已连线且数量、来源正确，也应补齐对应句子后再验收。同一连续动作里指代明确时沿用已有引用。

在交付可生成的工作流或将新编写的提示词标为 `ready` 前，将实际完成的审阅写入绑定当前输入摘要的 `editorialReviews`，说明所选写作依据、检查范围和具体内容。参数和引用核对不能代替写作检查；未检查的项目保持未检查，不批量填写“通过”。正文采用用户明确选择的其他写法时按其依据审阅，不因与内置示例不同或对白分列判失败。对获准改写的内容修复实际问题后再审阅，保留用户确认的风格与格式；只要求原样保存时不自动润色。保存后独立读回文本与参数，再在已有有效费用授权内生成。
