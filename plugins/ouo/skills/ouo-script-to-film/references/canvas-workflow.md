# 剧本工作流框架

本框架用于将剧本组织成用户能够阅读、修改和复用的制作工作流。用户未指定结构时直接采用；用户明确的需求、示意图及已有工作流决定相应调整。结构选择不代替目标画布权限或生成费用授权。

搭建中断或编辑会话过期时，按 [编辑中断与恢复](../../ouo-business-generation/references/canvas.md#编辑中断与恢复) 核实原保存结果，优先恢复原操作；需要新补齐方案时，先核实缺项再交用户确认。旧操作不可重放不等于整个工作流无法继续，保存结果未知仍沿原操作核查。

## 开工前制作规格

开始拆镜和搭画布之前，一次询问尚未给出的必要选择，并等待用户回答：

| 选择 | 需要确认和保存的内容 |
| --- | --- |
| 成片画幅 | 横屏、竖屏或其他，准确比例，例如 16:9、9:16、1:1；“竖屏”尚不等于确定 9:16，角色和道具参考图另按素材规格设置 |
| 视频模型 | 从当前空间实时目录提供可用选项，用户可选择单一模型或多个模型混用；不能用研究文档当可用目录 |
| 时长与模式 | 读取每个候选模型的当前参数和 rules，说明该模式的离散时长或上下限、参考输入和声音限制；15 秒、30 秒等只是实际契约可能提供的范围，不固化为规则 |
| 混用分工 | 哪些段落需要长片段，哪些用短片段；用户也可明确让 Codex 在已选模型范围内按动作和对白分配 |

用户已有明确选择时直接复用；用户要求推荐时展示基于当前目录的建议供其选择。可以继续读取原稿和做事实提取，缺少这些选择时先不冻结分镜数量、片段时长、视频参数或布局。用户明确委托代选时，在委托范围内选择并先告知实际方案。

同时读取制作契约的合成限制。当前 `video_merge` 仅暴露分辨率档位，非 16:9 输出尚缺可核验的比例控制，不能保证竖屏或其他比例成片。用户选择这些画幅时，在开工阶段说明合成缺口并保留其选择；可按已授权目标完成文本与工作流，整集合成保持未就绪，不等到生成片段后才说明，也不改成横屏。不能为此添加未获授权的收费转换任务。

支持新制作契约时保存 `preferences.aspectRatio` 与 `preferences.videoModels`，后者使用实时目录的准确 `modelName`。镜头各自保存 `durationSeconds`、`prompt.stagePrompts.generate_videos.modelName` 及 `modelParam`，实际比例和时长传入所选模型的真实参数字段。没有全剧统一的时长上限：例如当前契约确实分别支持 15 秒和 30 秒时，20 秒完整对白可分给后者，短动作使用前者；不为凑满上限拉长短镜头。超长对白在语义和动作接点拆开，不删对白、不换成快读。模型、模式或画幅变化后重新核对受影响分镜和提示词，保留旧版本和原任务回执。

逐镜先估算完整动作、人物调度、对白、停顿及运镜需要的时间，再从该模型与模式支持的组合中选择能承载内容的时长。连续对白和并行动作按实际重叠关系安排；复杂调度也可在自然切点拆镜。参数查询中的 `defaults.duration` 是原生初始化值，搭建工作流时应由本镜规划覆盖。用户已明确统一时长时按其要求组织内容。

当前契约要求首帧模式使用 `adaptive` 时，保留这个真实参数，依据准确首帧媒体的已保存宽高核对用户画幅；不能强改成 `9:16` 等不规范参数。读取与该 URL 对应的媒体尺寸，节点在画布上的显示宽高不能作媒体尺寸。尺寸未知时先准备并核验素材，不能宣称画幅已核对。需要固定片段时长的制作流程保存明确秒数；模型的智能时长不自动等于已经审阅的分镜时长。

## 每集的默认结构

以下表示默认的逻辑制作关系；实际空间组织按 [画布布局](../../ouo-canvas-layout/SKILL.md) 选择。根据真实场次、素材复用和审阅任务形成内容簇，主线在清楚的接续处可以转向；不预设全图列数和矩形外轮廓：

```text
本集剧本文本 -> 本集脚本（原稿与制作索引）
共享角色图 / 场景图 / 道具图 / 角色音色 -> 视频分镜 -> 本集合成
```

角色、场景和道具保留准确身份、类别与复用关系，按实际使用区域安排位置；跨场次或跨集共享素材放在有关内容簇之间、引用密集处或既有公共区域。各组素材分别连接需要它们的视频分镜，每个分镜可以引用多个素材，同一素材可以供多个分镜使用。节点在画布上的先后位置不替代准确引用和已保存的剪辑顺序。

原稿和脚本不连接到视频节点，也不传入视频的参考区。脚本表是制作索引，不是媒体；不能让其分镜 JSON 成为“文本参考”。视频提示词由分镜依据独立编写，不能依赖输入连线把整份脚本带入。

| 部分 | 默认节点职责 | 数量与组织 |
| --- | --- | --- |
| 剧本文本 | 保存本集完整原稿，保留对白、场次和顺序 | 每集一个文本节点；确实超过原生上限才按场次分段并编号 |
| 本集脚本 | 集中呈现提取的角色、场景、道具、分镜及每镜使用的素材 | 每集一个主脚本节点；达到真实容量限制时按连续场次分段 |
| 角色图组 | 默认纯白底、16:9、同一角色的正侧背全身三视图合为一张，含必要年龄、形态、服装变体 | 同一身份或必要变体建立一次；只发声的角色保存声音归属 |
| 场景图组 | 可跨镜头复用的空间参考 | 按真实空间建档；门边、窗边和机位变化通常共用基础场景 |
| 道具图组 | 默认纯白底、1:1、完整居中的关键物件 | 同一物件交接仍复用；仅在需要独立参考时建立图片节点 |
| 角色音色 | 每个角色独立的音色参考，记录真实声音归属 | 每个稳定角色一个基础音频入口，包含旁白、OS 和只发声角色；跨镜头、跨集复用 |
| 视频分镜 | 可由所选模型生成的片段，保存画面、动作、声音与提示词 | 按集内剪辑顺序编号；叙事小镜头可以合并在同一生成片段中 |
| 本集合成 | 汇集本集片段，按已保存顺序拼接 | 每集一个 `video_merge` 节点 |

不为每条实体、状态、原稿出处、审阅或任务另建文本节点。完整原稿与制作数据持久保存，不为了显示所有内部数据而扩大画布。用户要求资料表或调试视图时，按其目的单独呈现。

本集不需要某类素材时不创建该类的空节点。需要生成的素材先建立准确类型的图片、视频或音频占位，并连到真正使用它的分镜。保持 MCP 创建来源，未生成时在原生参考区保留待生成槽；不放入假 URL、假成功状态或素材说明文本代替占位。原生分组要求至少两个成员时，单个素材使用清楚的节点名称表达类别，不新增无用途节点凑组。节点数量取决于制作需要，不预设四镜头、固定角色数或固定总节点数。

## 共享素材图规格

以下是短剧工作流新建或明确改写共享参考图的默认规格，用户明确要求优先；独立图片创作、已有上传或已确认素材按其自身用途处理，不因格式差异自动重做。

| 素材 | 背景与实际输出比例 | 图内内容 |
| --- | --- | --- |
| 角色标准图及必要变体 | 均匀纯白背景，16:9 横幅 | 一张图内从左到右为同一角色的正面、人物左侧面、背面全身三视图；身份、服装、体型、尺度、脚底基线与光照一致，头顶至鞋底完整，视图间有间隔 |
| 道具标准图及必要变体 | 均匀纯白背景，1:1 方图 | 单件物品或剧本明确的一组物件完整居中，轮廓、关键结构和材质清楚，四周留白；不含持有者、手部、桌面或剧情环境 |
| 场景图、静态分镜 | 按场景用途、镜头构图和用户要求分别设置 | 场景保留真实空间；静态分镜保留本镜需要的角色、动作与环境，不套用白底或三视图 |

角色标准图采用中性站姿、自然垂臂、平视和柔和中性光。白底不替换为浅灰、米色、彩色渐变或摄影棚布景，不添加装饰边框、额外头像、表情小样或文字标签；主体仍保留必要的体积明暗与材质。道具不自动改成三视图或拆解图，保留原有必要标识。

素材图比例不继承 `preferences.aspectRatio` 或视频参数。即使成片为 9:16，默认角色图仍为 16:9、道具图仍为 1:1；成片比例继续沿用用户选择。先读取图片模型的实时 schema 和 rules，把对应比例显式写入该模型真实支持的参数字段，再保存到实际生成步骤的 `parameters.model_param`；有对应镜头图片阶段时同步其 `stagePrompts.generate_images.modelParam`。不猜字段、不只在提示词里写比例、不沿用模型默认值，也不将节点显示宽高当作媒体尺寸。模型不支持所需规格时说明具体缺口并按当前授权选择可用方案，不静默换比例。

一张角色三视图按一张图片设置数量及报价，不能将三个视图误当三个角色或三个输出。保存后独立回读正文、实际模型参数和节点版本；`generationSettingsApplied=false` 时，明确参数仅保存于生成步骤，原生控件尚未确认同步。生成后另查真实媒体宽高及画面中的白底、三个方向、全身完整度和外观一致性，任务成功不等于规格验收通过。旧任务恢复继续使用原参数和回执，新增或修改生成意图仍需匹配真实费用授权。

具体正文写法见 [图片提示词编写与审阅](image-prompts.md#短剧共享素材规格)。

## 提取与分镜对应

先读取完整剧本，归一角色别名，确认空间边界和具体物件身份，再为本集建立分镜。完整目录、稳定身份、状态事件与原文出处保存在制作记录中；脚本节点是本集的制作索引。

每条分镜能回答：谁在什么地方、做什么、谁发声、需要哪些角色/场景/道具参考、与前后镜头如何衔接。使用原生脚本的人物、场景、参考、动作、对白和时长字段保存相应内容；同一实体继续使用准确的稳定引用。

逐镜核对原生字段，不能只填 `description` 和视频提示词：

| 原生字段 | 填写依据 |
| --- | --- |
| `duration`、`description` | 真实规划秒数和可见画面；对应制作镜头的 `durationSeconds`、`description` |
| `characters`、`sceneName` | 本镜实际角色与状态、所在场景；人物保留稳定身份，不能把同名人物合并 |
| `action`、`dialogue` | 可拍的动作过程；对白逐字保留说话者、语种及对白/OS/旁白类型，无对白明确写“无对白” |
| `emotion`、`lighting` | 有剧情依据的情绪变化、光线方向与时段；未知内容标为待定，视觉补全注明创作选择 |
| `scene`、`focalLength`、`sceneTag` | 景别/构图、已有焦段或待定、原稿场次标记；不凭标题猜焦段或场次 |
| `reference` | 实际选用的角色/场景/道具及用途摘要，未有素材注明待补，不伪称已有媒体 |
| `soundEffect` | 环境声与动作声，有声来源明确；无额外音效如实填写 |
| `shotPrompt`、`motionPrompt` | 有独立图片需求才填静态提示词；视频提示词按专门规则完整编写，不能互相复制冒充 |

支持 `shots.storyboard` 时，将上述动作、对白、情绪、光线、参考、景别、焦段、场次和音效保存在此结构中。图像和视频使用各自 `stagePrompts`，投影分别映射到 `shotPrompt` 与 `motionPrompt`。直接原生编辑则用 `write_script` 或准确的 `edit_script` 字段。旧记录缺字段时回查完整原稿补写，不能从提示词猜对白、填无意义占位符或以字段存在但全空声称已补齐。

当前脚本契约若只有 `characters`、`sceneName`、`reference` 等分镜字段，就用这些真实字段呈现人物、场景及可读的道具/素材对应摘要。完整目录仍在制作记录中，不编造独立角色库、道具库字段，也不把目录 JSON 写进脚本生成输入。脚本的 `prompt` 是生成输入，只有通过 `write_script` 等真实结构化动作保存的分镜才能称为已有分镜。专门目录或自动绑定未接通时明确说明能力缺口。

分镜表和视频节点按同一份剪辑顺序组织。两层拆镜先完成叙事表达，再依据模型时长组成片段；不要将每句对白、每个小动作都变成独立视频节点。超出原生容量才分段，不按任意固定批量复制整套素材。

## 素材复用与视觉变体

规划图片前，先检索当前授权空间的用户上传、素材库及已有制作结果，再按身份、外观状态、用途和可用性匹配。后续镜头引用同一素材来源，跨集延续同一实体，避免同名重建和重复生图。

连续性状态与独立参考素材分别判断：

- 换持有者、走到门口、抬手、表情、临时湿度、光照或镜头角度等变化仍需记录并写入有关镜头；这些变化不自动产生新图片任务。
- 年龄、形态、明显服装或损坏等差异，在现有参考无法可靠表达且镜头确实需要时建立视觉变体，说明用途并让多个镜头复用。生成角色与场景变体时，按下文的母图派生规则执行。
- 仅发声的角色保留声音归属；背景人群和一次性环境细节按剧情需要表达，不为了凑齐目录逐项生成立绘或道具图。
- 图片节点用于实际素材或必要的待生成素材；描述清楚素材缺口，未生成时不声称已有图片。

复用必须满足当前工具的准确实体、状态与用途契约。不能将完整衣服的图绑定成破损状态，或改写来源标签让旧图冒充新图。若当前契约无法表达基础身份参考与临时状态的区别，保留具体缺口并说明限制；不以批量创建状态图或伪造绑定掩盖能力差异。

### 角色和场景变体的母图

每个角色、每个场景分别选定第一张已确认的基础图作为母图；母图可以来自用户上传、可用素材库或已核验的生成结果。这里的“第一张”指该身份或空间已确认的基准图，不能取画布排序最靠前的无关图片。没有母图时先补齐并确认基础图，再生成需要的变体。沿用用户已给的选择和当前执行方式完成基准核验，不新增逐张母图审批；生成仍须匹配原有费用授权。

角色的服装、年龄、发型、形态等变体，以及同一场景的日夜、季节、布置、破损和视角变体，默认基于该母图走图生图。提示词描述需要改变的部分及需要保持的身份或空间依据，避免每个变体从文字重新设计。不同角色或不同物理空间分别建基础图，不为减少节点而错误共用母图。

使用当前模型真实支持的图生图/参考图字段传入母图媒体，例如契约支持的 `image_ref`；只在提示词写“参考第一张图”或只画连线不算传入参考。需要从前一变体继续变化时，可以按模型能力增加该变体作为补充参考，同时保留原始母图来源，避免多轮派生丢失基础依据。

制作记录保留母图、变体的实体与状态、真实媒体来源及派生关系；画布把母图与必要变体放在同类素材区，使用真实支持的引用，不额外增加“母图说明”文本节点。已有准确变体直接复用。所选模型不支持图生图或缺少可用母图时，说明具体缺口并提供支持的选择，不静默退回独立文生图；用户明确选择其他参考或方式时按其要求执行。

跨集素材默认共用原节点及媒体来源。需要在不同区域显示同一素材时，按工具支持复用已有媒体，保留同一来源，不重新生成。同一节点的分组归属遵循原生规则，不假定它能同时属于多个父组。

## 角色音色与引用

除用户明确要求不使用素材引用外，每个视频分镜默认必须将本镜所需媒体写为提示词中的原生 `@` 引用，包括待生成的图片、视频和音频占位。仅搭建工作流或用户没有主动要求“加引用”时也执行，不为默认引用另行询问；按本镜实际用途选择准确来源，不把全部素材连入所有镜头。

每个角色保存独立音色入口、声音描述、已有音频来源和当前声音工具返回的真实声音标识；包括叙述者、OS 和从未出镜的角色。没有已确认素材时创建待生成音频节点，不能用同一默认声音覆盖所有人物，或仅写一句“成年男声”就声称已有音色。角色外观状态与声音归属分别判断，闪回中的幼年外观不自动改变成年旁白。

制作图沿用现有字段约定：音色素材和需求使用 `role=voice`、`mediaKind=audio`，并绑定准确的实体和基础状态。每个发声镜头在 `assetRequirements` 显式列出实际说话者的音色需求；同名人物按 `entityId` 区分。当前素材绑定要求 `stateId` 时先保存准确基础状态；不能编造状态或把未经核验的外观状态当声音身份。镜头的临时外观不同而音色相同时，音色需求明确引用原基础状态；无发声的角色不因此自动成为本镜音频输入。

先复用已授权音色或已有音频；需要新音色或对白时按当前真实的 `voice_timbre`、`voice_synthesis` 等工具契约准备并取得费用授权。音色样本、声音标识和逐镜对白音频是不同对象，不能互相冒充；视频模型不支持音色/音频参考时保留独立声音计划及缺口，不把画布连线描述为模型已经使用音色。

原生 `@` 引用必须由 MCP 写进提示词：先连接素材，再调用 `edit_canvas` 的 `set_prompt`，按句中位置交错传入 `parts`。文字是 `{kind:"text",text:"…"}`，引用是 `{kind:"reference",source_node_id:"准确节点或$本批key",media_kind:"image|video|audio",output_index:0}`。它完整替换提示词，原有需要保留的内容也要放入文字片段；目标仅支持图片/视频生成节点，省略 `connection_id`。已有目标和来源先回读并传 `expected_nodes`；同批先创建、连线，再用 `$key` 引用。服务按原生素材排序编译真实标记，不手写猜测的序号，不把普通“@角色名”当作原生引用。

每个引用都要逐项指代具体主体与用途，例如“女主外观：〔女主图原生引用〕；银行经理外观：〔经理图原生引用〕；场景（银行营业厅）：〔营业厅图原生引用〕；女士鞋（女主持有）：〔鞋图原生引用〕；女主声音：〔女主音色原生引用〕”。使用“主体：引用”或“主体=引用”均可；不能只写“人物外观：引用 引用；场景：引用；道具：引用”，也不能只依赖素材芯片中的名称让模型猜归属。多个角色、场景、道具或不同状态分别写清，外观和声音分开，持有者有剧本依据才标注。身份或用途不明先核对原稿、制作实体及准确来源，不按连线顺序猜测。

以下 `parts` 示范仅说明“主体文字紧邻真实引用”的写法，来源键须替换为当前批次已创建并连接的准确节点；正文其他内容也须一并保留：

```json
[
  {"kind":"text","text":"女主外观："},
  {"kind":"reference","source_node_id":"$lead","media_kind":"image","output_index":0},
  {"kind":"text","text":"；银行经理外观："},
  {"kind":"reference","source_node_id":"$manager","media_kind":"image","output_index":0},
  {"kind":"text","text":"；场景（银行营业厅）："},
  {"kind":"reference","source_node_id":"$lobby","media_kind":"image","output_index":0},
  {"kind":"text","text":"；女士鞋（女主持有）："},
  {"kind":"reference","source_node_id":"$shoes","media_kind":"image","output_index":0},
  {"kind":"text","text":"。\n女主直视经理，经理移开视线。"}
]
```

保存后逐项对照主体名称、用途、状态与真实 `source_node_id`，独立回读引用和正文；仅确认存在 `@` 不算指代审阅通过。创作正文中的自然语言规则不禁止画布编译提示词包含上述指代；模型的引用标签及媒体参数仍按所选模型真实契约分别核验，不将画布标记直接当作模型输入。

目标使用普通图片/视频生成节点。专用工作流和视频编辑草稿有额外的素材目录，当前 `set_prompt` 明确拒绝；不能用普通目录猜序号或把草稿原视频当作连接来源。

占位与其首个结果使用 `output_index:0`，生成完成保留来源节点、引用键和原生标记，无需重新选素材。投影或直接编辑建立连接后仍须执行 `set_prompt`，逐个视频节点独立回读提示词及准确来源；素材尚未生成时应读到待生成引用，不能等生成完成才补。缺少本镜必要引用时继续补齐，不能把“已有连线”报告为“已插入 @”或工作流搭建完成。同时用实际模型参考字段传入媒体。若当前已连接服务未暴露新动作，明确该服务需要更新并保留未完成项，不编造成功回执。

生成准备绑定已有目标时，保存的原生提示词与模型实际请求分开核验：已有原生引用会保留，模型正文及媒体参数仍取已审阅的制作参数；检查回执的保留结果，再独立回读原节点。改写剧情要先用 `set_prompt` 更新文字和引用、回读新修订，同时更新制作中的模型正文与参数，再准备新的生成意图；不以普通 `update.prompt` 写回模型正文而擦掉引用。同键换提示词或模型参数会被拒绝，重启继续原意图和任务；旧凭据不自动改写。

素材准备完成后独立读取原节点及下游视频，确认图片、视频、音频引用均指向正确来源、已解析真实结果且不再待生成。选择或连接仍待生成的素材时阻止提交视频；不能丢弃空槽继续生成。已有上传/素材库媒体优先在搭画布前选定；后补上传导致来源节点变化时使用当前契约显式核验和调整连线，不声称旧占位已自动获得另一个节点的媒体。

## 内容和参数

新的媒体制作步骤默认先保存并独立回读目标节点，再提交生成；已经连接分镜的素材占位通过步骤 `canvasTarget={nodeId,expectedEditRevision}` 显式绑定，修订来自该节点当前 `editRevision`。先核实实时步骤 schema 支持此字段；省略时仍会创建新目标，不能视为占位回填。每次尝试持久保留节点与原任务绑定，完成后将首个结果回填同一节点。一个运行中的不同媒体步骤不能共用同一目标；重试保留原产物并使用独立目标。`advance_production_run` 可恢复原回填，已完成 run 也可继续核对，`max_submissions=0` 不新建目标或提交生成。保存不明、受理不明或重启后沿原步骤和操作恢复，不创建替代节点重提。用户明确要求直接生成图片或视频时，普通生成入口才可选择 `execution=direct`。

读取当前回执核对原生模型、时长、比例等控件的同步状态。投影返回 `generationSettingsApplied=false` 时，按当前原生编辑契约补齐视频节点参数。新建或更新视频时显式写入本镜的 `parameters.duration`，从该模型、模式及分辨率支持的组合中选择；保存后独立回读原生时长，与脚本分镜 `duration`、制作记录 `durationSeconds` 及生成参数逐镜核对。下表列出内容的保存位置；尚未完成的参数同步应在交付中说明。

| 内容 | 保存位置 |
| --- | --- |
| 本集原稿 | 剧本文本节点和带来源的制作记录 |
| 提取结果、分镜表和素材对应 | 原生脚本结构及制作记录 |
| 需要生成的画面、动作、镜头语言、对白和声音 | 保留用户或所选写作 Skill 格式的图片或视频提示词 |
| 模型、时长、比例、分辨率、数量、音频开关 | 原生参数控件与对应生成参数 |
| 实体/状态 ID、状态补丁、来源范围、版本、任务回执和检查结论 | 制作记录和操作记录 |

例如视频提示词可以写：“雨夜的旧宅门前，人物沿用角色参考图中的外观。他将钥匙交给同伴，镜头从两人的中景推近到接过钥匙的手部，雨声持续。”模型、时长、比例和参考媒体通过对应参数设置。

不在提示词中粘贴 `stateId`、`sourceSpans`、状态字典或任务管理数据，不用“准确状态：{...}”代替所需画面内容。用户或所选 Skill 的声画表、分镜脚本和模型支持的结构化写法可以保留，不因采用 JSON 或不同栏目而改成自然段。工具所需的结构化 JSON 正常传给工具；接口明确要求的参考标签或时间段格式按真实契约编译，不混入实际播放的对白。用户明确要求导出数据时可以单独交付结构化文件。

## 布局与连线

- 每集一个清楚命名的制作区域，原稿与脚本入口、内容簇和合成成果容易找到；多集之间按实际复用关系和已有布局安排接续。用户指定竖排或现有布局时沿用其方向。
- 按真实场次、连续情节和共同引用组织镜头的空间邻域，局部保留便于审阅的顺序；角色、场景、道具按实际使用者安排，不固定为素材列与分镜列。节点使用角色名、地点名、物件名或“镜号 + 内容”的可读标题，技术 ID 保留在记录中。
- 根据节点实际尺寸、成员数量和分组边界留间距；避免标题遮挡、节点重叠、过大留白和延伸到难以浏览的长条。长集可以按连续场次分区，保持镜号与合成顺序。
- 最后一次排版、模型/比例变更或脚本展开后重新核对组边界：四边覆盖每个成员的实际显示矩形与外置标题，父组覆盖所有子组和子组标题。优先先排版再分组；原生批次支持时可同批执行。独立回读成员与 `bounds`，不能仅凭节点的 `groupId` 判断包住。浏览器中发现显示尺寸与保存尺寸不一致时，保留问题并用实际尺寸修正，不能只看节点中心坐标。
- 每个分镜只连接实际需要的素材。共享素材直接引用原素材节点；不要全量连接三组素材、按纯剪辑顺序串联生成依赖，或为了表达身份继承增加中间文本节点。
- 所有必要的空媒体先连接并保留待生成引用槽；素材生成回填原节点，不能复制出与分镜失联的新结果。脚本、状态字典和原稿说明不连接到视频输入。
- 文本到脚本的来源关系、素材到视频的参考关系、视频到合成的输入关系分别使用工具支持的连线。分组和连线本身不证明参考媒体进入了模型参数。

先完成一集的结构核对，再将同一组织方式用于后续各集。核对属于正常执行，无需为默认框架、每集或每个保存批次额外索要确认；真正缺少目标、关键内容或费用授权时按相应规则处理。

## 保存与完成标准

按 [制作工具与数据](tools-and-data.md#画布和成片) 读取当前契约并选择编辑入口。分批执行时保持布局和稳定映射，保存后独立回读节点、脚本、分组、连线及参数。

制作运行受理媒体任务后，在同次 `advance_production_run` 中将任务号和生成态保存到原节点；后续 advance 查询原任务并同步排队、运行、失败、取消及结果回填。核对步骤的 `canvasTaskState` 和最终回填回执，状态保存失败不等于任务未受理，不能换步骤或任务标识重提。画布打开与否不改变任务归属，前端不接管 MCP 来源任务；当前没有后台常驻轮询，Codex 必须继续推进原 run。暂停或取消制作运行不代表已受理的业务任务被取消；恢复时读取原任务及回执，保留用户修改、未知结果和原计费记录。

报告工作流搭建完成前核对：

- 本集原稿完整，脚本表中的分镜和素材对应清楚；不存在用摘要代替原稿的情况。
- 素材的新增和复用有依据，没有逐镜头复制角色、场景和道具，也没有将所有状态展开成节点。
- 新建或明确改写的角色、道具图已分别按白底 16:9 全身三视图、白底 1:1 物件图保存正文和实际比例参数，或保留用户明确的其他规格；成片比例未被素材比例覆盖，真实媒体另行检查。
- 画布文本、分镜内容及生成提示词均可读，内部管理数据留在制作记录。
- 视频分镜顺序与合成一致，每镜只引用所需素材；生成前另查真实媒体的模型参数绑定。
- 除用户明确要求不使用素材引用外，已逐个回读视频节点提示词，核对本镜所需素材的原生 `@` 引用及准确来源；未生成素材保留主输出待生成引用。缺少必要引用时工作流尚未搭建完成，不能只凭连线或投影同步成功交付。
- 每个角色都有独立音色入口，发声镜头绑定准确音色；媒体完成后原生 `@` 引用仍指向原节点并已解析真实结果，没有用普通文字标签或空音频冒充绑定。
- 分组、节点位置、脚本字段、连线和参数已有保存回执及独立回读；有浏览器预览时检查整体可读性，否则明确视觉布局尚未核验。
- 区分“结构已保存”“素材待补”“视频待生成”“已合成并播放检查”，不以空节点、连线或时间线代替真实媒体交付。

修改已有工作流前读取当前内容和准确修订，保留用户编辑及已有结果。用户否定旧方案或停止执行后，不能自动恢复旧批次；先核查原操作。需要整理或删除旧节点时，仅按本次明确修改范围处理，不从新框架推断清理整个画布的权限。
