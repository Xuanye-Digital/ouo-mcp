# OUO 插件维护

<!-- OUO_PLUGIN_VERSION: 1.0.0 -->

用户说“更新 OUO 插件”即可执行同一来源内的正常更新，无须重复发送安装引导或批准相同范围。普通创作、查看版本、“检查更新”“稍后提醒”“忽略此版”均不授权刷新市场或安装。

## 先区分操作

| 请求 | 执行入口 |
| --- | --- |
| 普通 OUO 创作首次使用 | [使用时检查](references/update-check.md)，自动网络预算最多 3 秒，失败继续原请求 |
| 查看当前版本 | 只读安装证据及当前加载版本；不刷新市场、不安装 |
| 检查更新 | 同一参考中的显式检查，必要时独立读取原 Git 来源；检查阶段不刷新市场 |
| 稍后提醒、忽略此版 | 对最近明确展示的 release 更新本地提醒状态，不安装 |
| 更新 OUO 插件 | 下方更新流程，并始终执行安全回读收尾 |

## 版本和来源证据

使用当前 Codex 宿主及其真实配置实例。优先读取宿主已核验无写入的安装信息和实际副本 `.codex-plugin/plugin.json`，记录 `version`、`enabled`、`marketplaceSource`、`source`、ref 与 `.mcp.json` 中的无凭据地址。安装路径由宿主或真实安装结果提供；不扫描所有配置目录、不读取 OAuth 状态、不猜缓存路径。

本 Skill 的版本标记表示当前已加载文本；[共享标记](../../.codex-plugin/skill-version.json) 与同一包 manifest 必须一致。安装版本与已加载版本分开记录；不能用市场清单、服务端版本或 MCP 客户端版本替代安装版本。

`codex plugin list --marketplace ouo --json` 不是已证明无副作用的通用检查入口：宿主可能同步安装副本。仅在该 CLI 版本已验证只读，或用户已授权更新后的核验流程使用它。无法只读取得真实安装信息时，报告“当前安装版本/来源尚未核验”，仍可查看独立公开发布信息，不生成安装动作。

## 用户要求更新

正式市场名为 `ouo`，插件为 `ouo@ouo`，仓库为 `https://github.com/Xuanye-Digital/ouo-mcp.git`，ref 为 `main`，MCP 地址和 OAuth resource 均为 `https://ouo.xuanyeai.com/mcp`。以这些字段核对正式安装来源；同名的其他来源仍按实际配置处理。

1. 用已有只读证据记录本次实际版本、来源/ref、启用状态及连接地址。缺少可靠来源时先通过宿主安装信息核实；不能因市场同名就自动迁移官方源。核对目标发布，取得独立证据时记录内容摘要和兼容说明。
2. 同源 Git 更新前，在独立临时 Git 副本核对当前配置的来源/ref、目标插件清单及连接配置。只有元数据的准确来源/ref/环境都匹配时才引用其发布结论。来源、ref、MCP/OAuth 地址或权限发生迁移时展示差异并等待对应明确指令；现有普通更新授权不覆盖迁移。
3. 使用当前宿主对应的 `codex`。CLI 不在 PATH 时查找宿主已知可执行文件，不新建配置实例。先用 `codex plugin --help` 核对命令，不支持时说明宿主缺口，不改写未知缓存。原本禁用时，刷新前先核实宿主有受支持的关闭入口；没有保留禁用状态的能力就说明限制，不执行可能启用插件的刷新。
4. Git 来源依次执行以下命令。市场刷新失败即停止后续安装；仍进入第 5 步。`plugin add` 失败或超时也进入第 5 步，不能继续重复安装。

   ```bash
   codex plugin marketplace upgrade ouo --json
   codex plugin add ouo@ouo --json
   ```

   只刷新实际匹配的 `ouo` 市场，沿用已配置的仓库和 ref，不使用 `marketplace add` 改源，不先卸载、不移除市场、不删除缓存。当前安装属于其他市场名时，使用已核实的原市场名和插件 ID，不能机械套用示例。

5. **从第一次实际市场刷新或本地 `plugin add` 开始，任何成功、失败或超时都执行安全回读收尾。** 已获更新授权后可用以下命令读取当前结果；核验命令本身失败时仍用宿主已知安装路径读取，不重复刷新。

   ```bash
   codex plugin list --marketplace ouo --json
   ```

   以真实 `installed` 及其实际路径回读 manifest、维护 Skill、共享版本标记和必要参考文件；核对当前来源/ref、MCP/OAuth 地址及原启用状态。原本禁用时，通过宿主受支持的插件开关恢复禁用，再回读确认；没有可用开关或回读失败就报告待处理，不绕过权限、不改未知缓存或整份用户配置。不能因为安装失败而跳过开关核对。
6. 安装版本与发布一致且能计算相同 `ouo-plugin-root-v1` 范围的摘要时，核对真实字节。版本相同但摘要不同应报告内容不一致；没有可比摘要时说明“版本已核验，内容摘要未核验”。分支在检查后前进时重新匹配实际安装结果；没有对应发布证据时只报告实际版本，不声称最初目标或最新已核验。
7. CLI 超时或返回不明时，先核实实际安装再判断下一步，不凭退出码不明重装、自动降级或清缓存。失败不覆盖 OAuth、任务或画布状态；插件版本恢复仅采用宿主已支持的能力并遵守用户授权。

本地目录或解压包只从原目录执行已授权的 `plugin add` 刷新，不能通过 Git 下载新文件。先核对原目录已收到新内容及连接地址；原目录不存在时说明缺口。本地刷新也执行第 5 至 7 步的失败收尾与状态核验。获取官方 Git 版需明确的来源迁移指令。未安装时，仅当用户也要求安装才执行现有安装流程；查看和检查不安装。

## 完成与恢复

按 [用户可见输出](../ouo-business-generation/SKILL.md#用户可见输出) 简明报告维护结果和可执行的下一步。普通更新失败不向用户索要服务源码、部署目录、内部日志或凭据；只有其明确要求技术排障时才展开必要细节。

分别报告发现发布、市场刷新、安装、实际版本/内容核验和当前聊天加载状态，失败说明停在哪一步。宿主有经过验证的重载入口时使用；无法证实当前聊天已加载新版 Skill 时提示用户自行新开聊天，必要时按宿主要求重启应用。不能声称更新缓存已热加载本次会话。更新授权不包含自动建聊、转发请求或续跑业务任务，相关动作须有用户另行明确指令。

更新不包含退出账号、清授权、报价、生成、写画布或恢复已停止的操作。实际收到认证失败时，当次按 [授权状态](../ouo-business-generation/references/generation.md#授权状态) 发起或加入一次宿主登录，不能只发提醒。回调成功但当前聊天仍无法访问时，按同一参考的“授权成功后仍无法访问”恢复原连接，后续重试也不直接再次登录。该章节统一规定认证分类、系统浏览器、重试及 CLI 兜底；网络或服务故障不触发重复登录。恢复后核验账户和原状态，不重提受理未知的操作或切换生成服务。

远程工具、模型目录和 MCP Apps 卡片的实际能力以当前连接为准；本地 Skill、清单或连接配置变化时需要更新包。公开发布信息、各客户端安装与当前聊天加载状态分别核验。
