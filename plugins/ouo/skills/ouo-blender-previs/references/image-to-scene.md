# 图片到本机 3D 场景

## 取得用户指定的图片

以当前连接的真实 Schema 为准，图片定位和查看均不调用生成服务。

### 画布图片

1. 沿用用户已指定的具体画布和节点；缺少具体画布时使用已有画布选择器。已选目标不重新让用户选一次。按业务 Skill 的[画布读取](../../ouo-business-generation/references/canvas.md)定位并保留当前 revision。
2. 对准确节点调用 `inspect_canvas`，设置 `view=media`、`media_scope=all`、`include_review_urls=true`，已有 revision 时传 `expected_revision`。按同一 revision 翻页，选择用户要求的 `kind=image` 和准确 `sourcePath`。区分生成输出、上传资源和输入参考；它们都可以作为本次用户选定的视觉参考，不能相互冒充。多图节点按实际图片及用户意图选择，不默认取第一张。
3. 使用宿主已有的图片查看能力，或在宿主浏览器中查看该项实际返回的非空 `reviewUrl`。实际看到图片后再分析；工具中的 `mediaAccess=not_probed`、`visualReview=not_performed` 只表示工具未看图，不能改写成已查看证明。不要把节点标题、提示词、缩略图占位或 URL 文字当作画面。
4. 查看不需要把图片先上传或收藏。缺少地址、地址失效、来源未获配置允许或宿主不能看图时，说明具体阻塞，请用户提供原图或在已有入口重新选择；不猜域名、不修改签名、不携带业务令牌访问图片站点，也不复制用户浏览器凭据。

旧工具未声明筛选或 review URL 字段时，先读取准确节点，复用当前已有媒体查看入口；没有可用查看能力就说明缺口，不发送未知参数。

### 用户上传图片

- 聊天中的可见图片直接查看；用户给出准确本地文件路径时用宿主看图能力读取该文件，不扫描图片目录。已提供且能查看的图片不要求再上传一次。
- 用户需要选择本地文件时，复用业务 Skill 的[原生上传卡](../../ouo-business-generation/references/assets.md#本地文件上传)。等待用户真正选图并上传，用原 `upload_id` 调用 `get_media_upload`；仅在 `registered=true` 后使用原 `mediaUrl` 实际查看。没有宿主可见本地路径时，不假定能读取用户在卡片里选择的文件。
- 已上传到画布的图片按上节读取。上传未完成或结果未知时沿原记录查询，不用建模要求代替文件选择，不重传以掩盖未知状态。

这些入口只提供视觉参考。需要把原图作为 Blender 纹理或随工程交付时，另按原来源的现有下载权限与文件读取规则处理；允许预览不等于允许导出原文件。普通布局建模可以直接依据已看到的画面制作，不要求先下载图片。

## 从画面搭建场景

记录实际可见的墙角、门窗、地面、主要家具、遮挡、物体朝向及光源方向，保留来源节点及字段或原附件身份。将已知尺寸与推测尺寸分开；缺少精确尺度时以合理比例继续，不强制增加确认步骤。

先搭地面、墙体、门窗开口，再放主要家具和道具。以单独命名的网格、曲线或实例保留可编辑结构，为 Blender 相机留出可移动空间。用参考机位调整透视、地平线、构图和物体相对比例，再从另一机位检查体积、开口与遮挡。不要用一张贴图平面或只对原机位成立的布景冒充完整场景。

第二视角存在时，对齐两图共有的门窗和家具锚点；若空间关系明显冲突，先指出冲突并采用用户已指定的主参考。未提供背面和尺度时允许合理补全，不能把补全部分描述为精确还原。复杂细节按用户要求逐步建模，不自动调用外部付费重建服务。

## 交付和验收

- 本地保存任务脚本及可重新打开的 `.blend`，保留原参考身份、已知条件与推测说明。工程需包含真实几何、可编辑对象及相机；有外部纹理时核实依赖完整。
- 实际查看参考机位和另一机位的渲染图，逐项比较主要空间和物体；有俯视布局需求时补充俯视图。存在动画需求才渲染并检查视频。
- 用户要求放到画布时，只将已检查的预览图或视频按主 Skill 的 OSS 直传流程导入准确画布，保存并独立回读，不修改原参考节点。
- 画布当前接收媒体预览，`.blend` 本地交付；不能声称画布已支持交互式 3D 工程节点。建模、导入和后续付费生成分别按实际完成状态报告。
