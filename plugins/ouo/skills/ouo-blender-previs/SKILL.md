# 本机 Blender 到 OUO 画布

<!-- OUO_PLUGIN_VERSION: 1.0.0 -->

由当前 Codex 直接使用用户本机 Blender：理解需求 → 编写并运行 `bpy` 脚本或使用已有 Blender 连接 → 保存 `.blend` 和预览 → 检查 → OSS 直传 → 导入现有画布。默认流程不要求另装本地 MCP、设备配对、签名检查点或建立专用制作记录。

首次使用按[插件检查更新](../ouo-plugin-maintenance/references/update-check.md)共用只读检查和 24 小时缓存。能力以当前工具为准，旧服务缺少本地产物上传入口时说明具体缺口，不伪造上传、远程能力或画布保存。

## 1. 确定当前任务

- 保留用户指定的剧本、画布、已有工程和参考。仅缺少会影响实施的信息时补问，其余按需求选择合理默认值。
- 先读取目标画布及当前编辑契约，确定导入位置；用户仅要本地模型时直接交付工程和预览。
- 核实用户现有 Blender 可执行文件及版本，或使用本会话已有 Blender 工具。只检查已知安装位置、系统命令或用户指定路径，不扫描整机。未安装时明确缺少 Blender，不自动下载大型软件。
- 使用用户指定的制作目录或当前任务独立目录。已有 `.blend` 先另存工作副本，保留原文件、纹理与外链说明；新版本用独立文件名。只打开可信工程，加载时禁用自动执行脚本。

## 图片输入

用户说“用这张图建场景”“画布里的图做 3D”或上传图片后要求建模时，按[图片到场景](references/image-to-scene.md)取得并实际查看准确图片，再进入制作。支持现有画布图片、聊天附件、明确的本地图片和原生上传卡中的图片；无需先生成另一张图、收藏素材或建立制作记录。

单张图片用于参考建模，不是已接入照片测量或自动图生 3D 引擎。已知尺寸和多角度图片优先使用；不可见结构及绝对尺度保留为推测。用户仅要静态场景时，交付 `.blend`、参考机位及另一机位的预览即可，无需生成角色、动画或视频。

## 2. 直接制作和渲染

以当前需求编写项目自己的 Python / `bpy` 脚本，不把用户需求限制为固定几何 Schema。已连接的 Blender 工具能够完成操作时直接复用，不再搭建一套常驻服务。

涉及白模视频、人物动作或运镜时，制作前读取[导演与表演调度](references/directing-and-blocking.md)及[Blender 镜头制作与验收](references/blender-shot-workflow.md)。用户已指定的分镜、风格和适用的导演 Skill 优先；这些指引用于落实当前要求，不授权修改剧情、补生成素材或扩大任务。静态图片建模不强制进入动画流程。

1. 从剧本和实际参考建立空间、角色目标及叙事节拍，区分原稿事实与创作选择。已有两个场景视角时同时核对门窗、墙体、家具和可见锚点；单图背面和尺度属于推测，不声称精确 1:1 还原。
2. 动画先写简短分镜计划，将观众注意对象、角色动作与反应、原句台词及时间、机位与焦距、移动起止和切点放在同一时间线上。每次移动、停留和切镜有叙事理由，时长不足时调整方案，不删句或强行加速。
3. 建立完整白模场景与稳定的角色标识。用关键姿态验证走位、重心、视线、道具接触和反应，再调整动作分解及插值；代理人缺少面部或手指能力时明确其表达限度。
4. 设置真实摄影机、画幅、传感器、焦距、帧率和逐镜帧范围；分别控制位置、朝向及焦点。检查连续画面的轴线、遮挡、穿模、速度与动作接点，不能只检查路径两端。需要台词时保留逐句时间与真实声音来源，标记不等于声音。
5. 保存任务脚本、分镜计划、可重开 `.blend` 和预览图；动画先做全时长低成本预演，检查后再输出所需 MP4。优先使用本机可用渲染器，失败按实际错误修复；只重做受影响镜头及必要接点。
6. 用户要求观看制作时，使用实际可见的 Blender 界面或可见预览。后台执行可以交付文件，但日志不能描述为用户已看到的界面操作。

后台调用形式以当前 Blender 的帮助和版本为准，常见形式：

```text
<blender> --background --disable-autoexec --python <本任务脚本.py>
```

按参考文档逐镜核验真实产物，区分计划审阅、工程检查、连续帧检查、正常速度播放与声音检查。采样图只能支持已采样画面的结论，不能宣称全片运动、表演或声音通过；无法播放时如实保留待验收项。交付保留版本和具体时间码证据。

## 3. 把预览导入画布

详细命令及恢复见[本地执行与上传](references/local-bridge.md)。用户要求“做好放到画布”等已包含该预览上传和目标画布写入意图，按原范围执行，无需额外配对；生成扣费仍单独确认。

1. 对准确预览文件运行本 Skill 的 `scripts/upload_local.py`，用 `--handoff` 指定本任务的全新交接子目录。使用实际脚本绝对路径，不猜插件根目录变量。脚本输出 `phase=prepare` 后保持同一进程等待，读取目录内 `prepare.json`。
2. 将文件内的 `params` 原样传给原生 `prepare_local_media_upload`。返回的 `ticket` 是密文，以 `{"ticket":"原密文"}` 写入该目录的 `ticket.json`；不解密、显示 STS 或另写业务 HTTP 客户端。
3. 脚本只向原 OSS 对象发送文件，结束后读取同目录 `complete.json`，将其中实际回执的 `params` 原样传给 `complete_local_media_upload`。只有 `registered=true` 才继续。SHA256 去重命中时复用原 URL，跳过文件发送和后端完成登记。
4. 用 `apply_uploaded_media_to_canvas`，按其实时 Schema 传入原 `upload_id`、准确 `project_id`、稳定 `request_id`，按需设置标题与位置。沿用现有保存、编辑会话及独立回读，不手写任意 URL 或任务成功状态。
5. 回读原画布确认资源节点、媒体、名称和位置；向用户交付可重开工程、预览与已保存节点。`.blend` 保存在本地，当前媒体上传不接受工程文件。

文件字节不经过业务后端或 MCP。当前脚本使用单次 OSS PutObject，最多 5 GiB；这不代表 OSS、业务账户或下游模型没有其他限制。默认保留原规格，不因浏览器卡片的 50 MiB 限制压缩。模型参考限制按实际能力检查。

## 4. 用户需要继续生成时

本地建模与导入完成即可交付。用户要求真人化或继续成片时，读取[白模到成片的交接](references/blender-shot-workflow.md#白模到成片的交接)，再按[剧本到成片](../ouo-script-to-film/SKILL.md)和当前模型契约执行：明确白模负责运动与时间，场景和角色参考负责外观与身份，将白模放入真实的视频参考字段；画布连线和提示词中的 URL 不代替模型输入。不强制逐镜首帧，不套用其他平台的模型名或模式名。

查询实际报价或用量规则，使用匹配的费用确认或有效静默授权。受理不明时查询原任务，不换标识重复提交。结果回填原节点并独立回读；首版成片按镜头顺序拼接。用户仅需建模或导入时，流程在第 3 节结束。
