# 轩晔 OUO 插件

通过 Codex 连接自己的 OUO 账号，查看项目、画布与素材，编辑创作内容，生成图片和视频，并跟进任务与结果。

插件版本为 `1.0.0`，使用正式 MCP `https://ouo.xuanyeai.com/mcp`。发布版本以本仓库 `main` 的插件清单为准。

## 创作与制作

- 根据画布图片、上传图片或剧本，由 Codex 直接使用本机 Blender 搭建可编辑 3D 场景。动画制作包含人物调度、表演节拍、机位与运镜、连续预演及逐镜检查；静态建模可独立完成。`.blend` 保存在本地，已检查的预览直接上传 OSS，再通过当前服务提供的原生工具导入指定画布。图片用于参考建模，未知尺度与不可见结构保留为推测；画布接收媒体预览。详见[本机 Blender](plugins/ouo/skills/ouo-blender-previs/SKILL.md)。
- 图片和视频创作使用当前账户可用的模型与参数。默认先保存并独立回读画布节点，再提交生成，结果回填同一节点；用户明确要求时可直接生成。分别核验原生控件、全部显式参数与真实生成结果；控件或额外参数未完整同步时说明具体限制。
- 支持按同一画布版本分块读取完整文本和完整分镜，核对内容长度与摘要后交付；不把预览当全文。素材重命名须由用户在卡片中确认，超时沿原请求查询；以当前服务是否提供相应工具为准。
- 服务声明相应参数时，已有文本/视觉描述任务可直接导出 TXT，已有脚本可直接导出完整 JSON/CSV，大素材文件信息可分块完整读取。保持原任务或原库记录、版本及完整摘要，实际文件保存后独立回读；旧服务按现有完整读取能力处理并说明缺口。
- CSV 含 `valueEncodings` 时可还原固定字段的原类型、空值与缺失字段；旧 CSV 缺少该列时不推断原类型，需要准确类型则使用 JSON。MCP 服务与插件分别核验发布状态。
- 媒体交付指引支持原样保留文件与水印；当前服务提供对应入口且团队素材明确允许下载时，可直接准备素材交付，无需先导入画布。读取前重新核验完整清单，实际文件须由宿主检查媒体、保存并独立回读；其他来源的权限和真实媒体交付仍分别验收。
- 剧本工作流先应用当前编辑或制作契约的 `workflowGuidance`，服务缺少该字段时使用随包共同参考。默认按每集剧本文本、脚本、共享角色/场景/道具/音色素材、视频分镜和顺序合成组织，支持按用户要求调整。开始拆镜前确认准确画幅、视频模型及各模式支持的时长；按动作、对白、停顿和运镜逐镜估时，显式保存并回读模型支持的实际时长，允许逐镜混用模型。
- 视频节点默认在提示词中引用本镜所需的准确素材，包括待生成的媒体占位，无需另外要求“加引用”。只有用户明确要求不引用时才省略；交付前逐个视频节点回读引用及来源，必要引用缺失时继续补齐，不能只凭连线或工作流同步成功判定搭建完成。
- 画布布局按任务与真实引用组织内容簇，安排共享素材、局部秩序和簇间留白；角色、场景、道具和音色形成可辨认的分类区域，首轮搭建就完成布局。创作工作流不固定为等宽分栏或整齐方阵。已有节点内容、素材来源、分组语义和镜头顺序按授权保留，保存后分别核对结构、几何与实际界面。
- 脚本保留对白、动作、情绪、光线、景别、焦段和音效等字段。静态图和视频使用各自的提示词；新编写或获准改写前默认读取对应内置写作 Skill 的 `writing` 和相关 `patterns`，示例按需，仅搭工作流时同样适用。用户明确指定其他 Skill 或写法时沿用其选择，原样保存正文时保留原文。审阅目标、事实一致性、声画对应及模型支持，保留所选风格与格式；声画表和结构化写法均可，不要求像内置示例。参数或引用核对不代替写作审阅；分组与布局在保存后独立回读核对。
- 优先复用上传、素材库和已有制作结果。角色和场景变体默认使用各自已确认的基础图进行图生图；视频默认直接使用准确的多参考素材，不强制逐镜头生成首帧图。
- 文本规划可由当前宿主 + Skill 完成，新执行选择使用 `host`，旧 `codex` 记录按实时契约兼容。图片、视频、声音和整集渲染需要真实可用工具及结果回传；当前 OUO 制作中的媒体阶段使用 OUO 生成服务，不能选择宿主执行后隐式转交 OUO。新审阅记录使用 `agent` 并绑定实际版本及证据，不把方案同意当作真实媒体验收。
- 当前整集制作按已保存镜头顺序使用 `video_merge` 拼接，核对完整镜头覆盖、片段来源、音画和首尾。字幕、转场、音量混合及自定义输出规格按实时工具能力处理；竖屏等画幅缺少合成能力时会在开工前说明，不静默改成横屏。

完整指引见 [业务创作](plugins/ouo/skills/ouo-business-generation/SKILL.md)、[画布布局](plugins/ouo/skills/ouo-canvas-layout/SKILL.md)、[剧本到成片](plugins/ouo/skills/ouo-script-to-film/SKILL.md) 和 [剧本工作流框架](plugins/ouo/skills/ouo-script-to-film/references/canvas-workflow.md)。实际可用范围以当前连接提供的工具契约为准。

## 账户与费用

项目、画布和素材操作使用当前用户已授权的空间与权限。个人素材、团队素材、上传登记和画布保存分别处理，完成一项不会自动授权下一项。

付费操作需要匹配任务的真实用户确认或有效授权。图片和视频报价是预估，最终结算可能高于预估；角色提取、场景提取和拆分镜须由实时契约明确支持不预消费、按实际 token 扣费，金额未知时也须先确认。缺少对应能力时可使用用户允许的 Codex 文本路径或保留待完成项。

用户可以选择逐任务确认、适用的限额模式，或“静默执行（按业务扣费）”。静默执行不设金额上限，仍限定同一执行计划、模型、阶段、有效期和重试次数。余额不足保留进度，充值后按原计划与有效授权继续。受理不明时查询原任务，不重复提交；用户停止的操作不会因更新或恢复连接而自动继续。

## 安装

将以下说明发送给 Codex：

```text
帮我安装 OUO 插件，让我可以在这里创作图片和视频。

1. 先核对当前是否已有名为 `ouo` 的市场。首次安装执行 `codex plugin marketplace add https://github.com/Xuanye-Digital/ouo-mcp.git --ref main`。已有同名来源时先核对仓库与分支，切换来源前由我明确确认。
2. 安装插件：执行 `codex plugin add ouo@ouo`，回读已安装版本及其 MCP 连接。
3. 使用当前聊天实际提供的宿主连接和授权入口；由我完成 OUO 业务账户授权后，只读核验账户与连接状态。若当前聊天无法加载新插件工具，说明具体缺口及需要我执行的刷新、重启或新开聊天操作，报告已完成的安装步骤。
4. 本次只安装和只读核验，不创作图片或视频、不写画布，也不恢复其他业务任务。除非我另行明确要求，不自动新建聊天、转发请求或创建续跑任务；交接摘要不代表我对业务操作的确认或费用授权。
分别告诉我安装是否完成、当前聊天是否已加载工具、账户连接是否已核验；全部就绪后再告诉我可以开始创作。
```

安装时需要能访问公开 GitHub 仓库。每位用户通过宿主提供的入口授权自己的 OUO 正式账户。

已安装本地目录或解压包时，先核对现有来源。迁移到上述 Git 市场需要明确的来源迁移指令；沿用本地来源更新则使用原目录。安装后优先核验当前聊天的工具加载状态；确实需要新聊天时提示用户自行新开，不自动创建或转交任务。

## 检查更新

选中并执行本插件 Skill 时，会复用同一配置实例、来源/ref、环境和版本证据下 24 小时内的成功检查。需要网络时总预算最多 3 秒，失败继续原任务。检查不会刷新市场、启用或安装插件，也不读取账户、余额、任务和画布。

可以说“检查 OUO 插件更新”绕过缓存。普通新版本只提醒一次，也可以说“稍后提醒”或“忽略此版本”。“稍后”表示下次使用且满 24 小时后再提醒，不是后台通知；宿主无法持久保存提醒状态时，仅支持当前会话去重。没有可靠的安装版本或来源时，会分别说明已发现的发布和待核验项。

版本检查读取本仓库 `main` 的公开插件清单。OAuth 断连时也可检查版本。详细规则见 [使用时检查](plugins/ouo/skills/ouo-plugin-maintenance/references/update-check.md)。

## 更新插件

在 Codex 中说：

```text
帮我更新 OUO 插件。
```

Codex 会核对原安装来源/ref、连接和启用状态，更新对应市场及安装副本，并在成功、失败或超时后回读实际状态。原本禁用的插件保持禁用；版本相同不代表内容摘要已核验。更新沿用原来源，不先卸载插件；来源、分支、连接或权限迁移需要对应明确指令。本地目录或解压包只从原目录刷新，不会自动从 Git 获取文件。

以下命令仅用于用户已要求更新的流程，供排查或旧版客户端使用：

```bash
codex plugin marketplace upgrade ouo --json
codex plugin add ouo@ouo --json
codex plugin list --marketplace ouo --json
```

前一步失败就停止后续安装，仍核实当前实际状态，不重复刷新或盲目重装。普通只读检查不使用这些命令；当前同名市场来自自定义仓库/ref 时，不按示例迁移来源。

完成后使用宿主经过验证的刷新入口。无法确认当前聊天已加载新版 Skill 时，说明限制并提示用户自行新开聊天，必要时按宿主要求重启。更新授权不包含自动建聊、转发请求或续跑业务任务；通常无需重新授权，明确的刷新令牌失效按宿主入口恢复连接。完整流程见 [插件维护](plugins/ouo/skills/ouo-plugin-maintenance/SKILL.md)。

## 连接与恢复

登录失效时实际发起或加入一次宿主登录，由宿主打开系统浏览器授权页，再提示用户完成页面中的登录，不能只给登录提醒或让用户自行寻找入口。等待同一次回调，成功后先只读核实原状态，再继续原只读请求；原始报错和内部诊断不直接展示给用户。支持该能力的卡片提供“重新登录”（旧版为“请求恢复连接”）入口。沿本次已确认的需求、已选画布和原任务核实状态，不自动重复生成、扣费或切换其他生成器。卡片能力以当前 MCP 服务为准，服务、插件发布及实际宿主流程分别验证。

连接异常时先按宿主实际错误恢复工具发现或授权，不自动使用临时脚本提交付费任务。网络、存储或容量错误不要求反复登录；只有明确的授权失效才重新授权，恢复后核验账户并继续原请求。已有任务沿用原任务记录，受理不明时先查询，不重新生成。

授权回调成功后，须在当前聊天只读核验通过才报告访问恢复。仍不可用时先恢复原连接，后续重试不直接再次授权；宿主没有可调用的重载入口时，提示重启宿主并回到原聊天重试，不保证恢复。详见 [授权成功后仍无法访问](plugins/ouo/skills/ouo-business-generation/references/generation.md#授权成功后仍无法访问)。

远程工具与卡片的实际能力以当前连接为准；插件包更新后也须分别核验安装与当前聊天加载状态。工具缺失时使用宿主受支持的刷新入口，并如实说明尚未接通的步骤。
